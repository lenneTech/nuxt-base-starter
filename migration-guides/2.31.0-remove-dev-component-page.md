# Migration Guide — 2.30.x → 2.31.0

Version 2.31.0 removes the interactive component page from the template and moves it to Nuxt 4.6,
which raises the minimum Node version.

The page was only built into dev bundles and nobody maintained it, and its examples already live in
real pages of the template: Valibot forms on the auth pages, `useOverlay` in
`app/pages/app/settings/security.vue`, toasts throughout. In generated projects it also occupied
`/docs`, the route a project wants for its real documentation.

**Existing projects are not affected until they take the changes.** `lt fullstack update` does not
copy template pages or bump dependencies, so both parts below are optional.

**Check Node before anything else.** Nuxt 4.6 declares `^22.22.3 || ^24.15.0 || >=26.0.0`. Nothing
warns you when a machine is below that: the template's own `engines.node` still says `>=22`, and a
build on Node 24.12 went through without a message. New projects created from 2.31.0 need a Node in
that range on every developer machine.

## What changed

| Area                  | Change                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Component page        | `docs/pages/docs.vue` and its demo modal `app/components/Modal/ModalBase.vue` are gone                                                                       |
| Layer                 | `docs/nuxt.config.ts` is gone and `nuxt.config.ts` no longer `extends` `./docs`. `docs/` stays as a plain folder for `e2e-auth.md` and `security-headers.md` |
| Build flag            | The `devBuild` constant and `appConfig.devBuild` are gone. Their only consumer was the "Interactive Examples" card on the landing page, which is gone too    |
| robots.txt            | `/docs` is no longer disallowed                                                                                                                              |
| `NUXT_PUBLIC_APP_ENV` | Unchanged. At build time it still decides whether the bug.lt reporter is baked in (any value other than `production`)                                        |
| Nuxt                  | `nuxt` 4.5.2 → 4.6.0, which brings `@nuxt/cli` 4 and cssnano 9. The template needed no code change                                                           |
| Node                  | Nuxt 4.6 needs Node `^22.22.3 \|\| ^24.15.0 \|\| >=26.0.0` (4.5.2: `^24.11.0`). The template's Docker image (Node 24.18) and CI (newest 24.x) meet it        |
| Overrides             | The `unhead` override is gone from `pnpm-workspace.yaml`: with `@nuxt/ui` 4.11.3 the tree resolves a single unhead major on its own                          |
| Tooling               | `oxlint` 1.87.0, `oxfmt` 0.72.0, `@iconify-json/lucide` 1.2.140                                                                                              |

## Upgrade steps — component page (existing project, optional)

Skip this if your project serves its own pages from the `./docs` layer; then only steps 1 (the
template page and `ModalBase`) and 3 apply.

1. Delete the template page in `docs/pages/` (`docs.vue`, unless you moved it) and
   `app/components/Modal/ModalBase.vue`. Check first that nothing else opens the modal:
   `grep -rn "ModalBase" app`.
2. Delete `docs/nuxt.config.ts`, and in `nuxt.config.ts` remove `extends: devBuild ? ['./docs'] : []`,
   the `devBuild` constant and the `appConfig.devBuild` entry.
3. In `app/pages/index.vue`, remove the "Interactive Examples" card, the `isDevelopment` computed, and
   `useRuntimeConfig()` / `useAppConfig()` if nothing else on the page reads them.
4. Remove `'/docs'` from `robots.disallow`, unless the project wants that path out of search engines.
5. Run `pnpm run check`.

`/docs` then answers 404 until the project puts its own page there.

## Upgrade steps — Nuxt 4.6 (existing project, optional)

1. Check `node -v` on every developer machine, the `node-version` in CI and the base image in your
   Dockerfile against `^22.22.3 || ^24.15.0 || >=26.0.0`.
2. Raise `nuxt` to `4.6.0` in `package.json`, then run `pnpm install`.
3. Keep an `unhead` override from an older template unless `pnpm why unhead` shows a single major
   without it. Two unhead majors do not break `nuxt dev`, only the built server: every SSR request
   then fails with `500 ERR_MODULE_NOT_FOUND`.
4. Run `pnpm run check`, which starts the built server once, or run `pnpm run build` and
   `node .output/server/index.mjs` and open a page.
