# Migration Guide — 2.38.3 → 2.38.4: locally, the verify-email page says where the link is

A freshly generated project runs its API without SMTP. Signing up then sends no mail: the API only
logs the verification link, in the line `[EMAIL VERIFICATION] … URL: …` of its terminal, among many
debug lines. The app showed "E-Mail bestätigen" and asked to click the link in the mail, so nobody
found it without being told.

2.38.4 shows a hint on `/auth/verify-email` while the page waits for the link: "Lokal ohne SMTP — Den
Bestätigungslink findest du im API-Terminal unter `[EMAIL VERIFICATION]`." It appears only when
`runtimeConfig.public.appEnv` is exactly `local`. Every other value, an empty one or none, shows
nothing, so a deployed stage never shows it. The Angular starter shows the same text in the same
place.

| Project                                 | What to do                                   |
| --------------------------------------- | -------------------------------------------- |
| Uses the starter's `/auth/verify-email` | Steps 1 to 3                                 |
| Has its own verify-email page           | Step 1 and the hint from step 2 in your page |
| Has no e-mail verification              | Nothing                                      |

No new dependency and no API change are needed.

## What changed

| Area            | Change                                                                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Page**        | `app/pages/auth/verify-email.vue` shows the hint "Lokal ohne SMTP" in its waiting state, only while `appEnv` is `local`                          |
| **Environment** | `.env.example` names the third role of `NUXT_PUBLIC_APP_ENV`                                                                                     |
| **Tests**       | `tests/unit/pages/auth-verify-email.test.ts` pins where the hint shows and where not; `tests/e2e/auth-lifecycle.spec.ts` checks it after sign-up |

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, the steps happen in `projects/app/`.

### 1. Check `appEnv`

The hint reads `runtimeConfig.public.appEnv`, which the template also uses for its bug reporter.
Check that your `nuxt.config.ts` declares it:

```ts
const appEnv = process.env.NUXT_PUBLIC_APP_ENV || (process.env.NODE_ENV === 'development' ? 'local' : 'production');
// …
runtimeConfig: {
  public: {
    appEnv,
  },
},
```

Under `nuxt dev` it is `local` without any variable, and a build without `NUXT_PUBLIC_APP_ENV` stays
`production`. Never set `NUXT_PUBLIC_APP_ENV=local` on a deployed stage.

### 2. Add the hint to the page

In `app/pages/auth/verify-email.vue`, after `SEND_FAILED_MESSAGE`:

```ts
const showLocalMailHint = runtimeConfig.public.appEnv === 'local';
```

In the waiting state, directly above the alert "Keine E-Mail erhalten?":

```vue
<UAlert v-if="showLocalMailHint" color="info" data-test="local-mail-hint" icon="i-lucide-terminal" title="Lokal ohne SMTP" variant="subtle">
  <template #description>Den Bestätigungslink findest du im API-Terminal unter <code>[EMAIL VERIFICATION]</code>.</template>
</UAlert>
```

Keep the comparison exact (`=== 'local'`). A check like `!== 'production'` would show the hint on
every staging or development stage, where the API does send mail.

### 3. Take over the tests

Copy `tests/unit/pages/auth-verify-email.test.ts`. Its new block "the hint for a local API without
SMTP" needs the page from step 2 and an `appEnv` option of the mount helper, which the copied file
brings along. In `tests/e2e/auth-lifecycle.spec.ts`, take the lines after
`await expect(page.getByText('E-Mail bestätigen')).toBeVisible(…)` that read `appEnv` from the
running app and expect the hint exactly when it is `local`.

```bash
pnpm run typecheck && pnpm run test:unit
```

## Check it

Start the API without SMTP and the app with `nuxt dev`, and sign up: `/auth/verify-email` shows
"Lokal ohne SMTP" above "Keine E-Mail erhalten?", and the link is in the API terminal under
`[EMAIL VERIFICATION]`. A build without `NUXT_PUBLIC_APP_ENV` (`appEnv` is `production`) shows no
hint.
