# Migration Guide — 2.38.2 → 2.38.3: the prompt management keeps disabled prompts

`GET /ai/prompts` answers the active prompts only, which is what the chat picker offers. The
management page `/app/settings/ai-prompts` loaded the same list. A prompt saved with "Aktiv" switched
off therefore vanished from the page right after the save: its owner could neither see it nor switch
it on again, and the "inaktiv" badge never had anything to show.

nest-server 12.7.0 lists the disabled prompts too on `GET /ai/prompts?includeDisabled=true`, and
nuxt-extensions 1.27.0 sends that parameter for `useLtAiPrompts().load({ includeDisabled: true })`,
for the reload after creating, changing or deleting a prompt as well. 2.38.3 raises nuxt-extensions
and lets the management page load with the option. The chat picker keeps the plain `load()`, so a
disabled prompt is never offered in the chat.

| Project                                            | What to do                                                |
| -------------------------------------------------- | --------------------------------------------------------- |
| Uses the starter's `/app/settings/ai-prompts`      | Steps 1 to 3                                              |
| Has its own prompt management page                 | Step 1, then call `load({ includeDisabled: true })` there |
| Removed the AI UI, or never calls `useLtAiPrompts` | Step 1 only, with the next dependency update              |

**The API side.** The page shows disabled prompts once the API runs nest-server 12.7.0 or later.
An older API has no such parameter, ignores it and answers the active prompts as before, so the
order of the two updates does not matter and nothing breaks in between.

## What changed

| Area                | Change                                                                                                                                                               |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Dependency**      | `@lenne.tech/nuxt-extensions` 1.26.0 → 1.27.0                                                                                                                        |
| **Management page** | `app/pages/app/settings/ai-prompts.vue` loads with `load({ includeDisabled: true })`                                                                                 |
| **Chat picker**     | Unchanged: `app/components/Ai/AiPromptPicker.vue` keeps `load()`                                                                                                     |
| **Tests**           | New `tests/unit/pages/ai-prompts-include-disabled.test.ts` and `tests/e2e/ai-prompts-include-disabled.spec.ts`; `resetTestData` also deletes the test user's prompts |

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, the steps happen in `projects/app/`.

### 1. Raise nuxt-extensions to 1.27.0

```bash
pnpm add -E @lenne.tech/nuxt-extensions@1.27.0
```

Vendor mode: update the core to 1.27.0 with `/lt-dev:frontend:update-nuxt-extensions-core`.

Take this step before step 2: up to 1.26.0, `load()` takes no argument, and `pnpm run typecheck`
fails on the new call.

### 2. Load the management list with the option

In `app/pages/app/settings/ai-prompts.vue`:

```diff
-onMounted(load);
+onMounted(() => load({ includeDisabled: true }));
```

Leave `app/components/Ai/AiPromptPicker.vue` as it is. A project with its own management page makes
the same change there, and nowhere a user picks a prompt to use it.

### 3. Take over the tests

Copy `tests/unit/pages/ai-prompts-include-disabled.test.ts`. It mounts the page and the picker and
fails when the page loads without the option or the picker with it, so take it together with step 2. It imports nothing from `@lenne.tech/nuxt-extensions` and runs unchanged in vendor mode.

Copy `tests/e2e/ai-prompts-include-disabled.spec.ts`. It runs only against an API with the AI
module (`GET /ai/status` 200) and skips otherwise (see `docs/e2e-auth.md`). Against nest-server
before 12.7.0 it checks the requests and notes the annotation `api-before-12.7.0` instead of
checking the "inaktiv" row.

Vendor mode: change the spec's import `from '@lenne.tech/nuxt-extensions/testing'` to
`from '../../app/core/runtime/testing'`, as in your other specs. The CLI rewrote those when it
vendored the core; a file copied later keeps the npm import, and `pnpm run typecheck:tests` fails on
it because the package is gone.

The spec creates prompts. So that `resetTestData` removes them with the test user, add this block
to it in `tests/e2e/helpers/auth-backend.ts`, after the deletion from `webauthn_challenge_mappings`:

```ts
// AI prompts name their author as `ownerId`, not `userId` (tests/e2e/ai-prompts-include-disabled.spec.ts).
try {
  await db.collection('aiPrompts').deleteMany({ ownerId: { $in: [userId, user._id] } });
} catch {
  // Collection may not exist (AI module off)
}
```

```bash
pnpm run typecheck && pnpm run test:unit
```

## Check it

Against an API on nest-server 12.7.0: on `/app/settings/ai-prompts`, save a prompt with "Aktiv"
switched off. It stays in the list, marked "inaktiv", and can be edited and switched on again. The
picker in the chat (`/app/ai`, "Vorlagen") does not offer it. In the browser's network tab the
management page asks `GET /ai/prompts?includeDisabled=true`, the chat `GET /ai/prompts`.
