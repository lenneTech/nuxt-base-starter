# Migration Guide — 2.32.1 → 2.32.2

Version 2.32.2 corrects two SEO defaults that every generated project inherited. nuxt-og-image
(part of `@nuxtjs/seo`) is now disabled until a page defines an OG image. Before, it served an image
renderer under `/_og` that nothing used, and it warned on every `nuxt dev` start about a signing
secret that changes with each build. The landing page now carries a meta description; before, it had
none, so `og:description` was empty as well.

Projects created with a current `lt fullstack init` get both. **Existing projects do not**: the files
involved were copied when the project was created. Nothing here is breaking and every step is optional,
but step 1 removes a runtime endpoint nobody uses, and step 3 fixes a visible bug in projects created
before 2.29.0.

## What changed

| Area                  | Change                                                                                                                                                                                                                                                                                                |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OG images**         | `nuxt.config.ts` sets `ogImage: { enabled: false }`. The module skips its setup: no `/_og` routes, no signing secret, no dev warning. `defineOgImage*()` resolve to no-op mocks, so a call still compiles but does nothing                                                                            |
| **Landing page head** | `app/pages/index.vue` calls `useSeoMeta({ description })`. The constant is also the hero subtitle, so the meta description cannot drift from what the page says. `og:description` is inferred from it                                                                                                 |
| **Tests**             | `tests/unit/og-image-contract.test.ts`: no `defineOgImage*()` under `app/` means the module must be off; enabled means `.env.example` must document `NUXT_OG_IMAGE_SECRET`. `tests/e2e/landing-seo.spec.ts` reads the server HTML of `/`: one title, no "X \| X", description equal to og:description |

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, every path below is relative to `projects/app/`.

### 1. Switch nuxt-og-image off, or give it a fixed secret

Check whether the project defines OG images at all:

```bash
grep -rn "defineOgImage" app/
```

**No hits** (the usual case): add this block to `nuxt.config.ts`, next to the other SEO options.
Copying the comment from the template's `nuxt.config.ts` as well tells the next reader how to switch
it back on.

```ts
ogImage: {
  enabled: false,
},
```

`nuxt dev` then logs `[@nuxtjs/og-image] The module is disabled, skipping setup.` and the secret
warning is gone. Nothing else in `@nuxtjs/seo` depends on it: sitemap, robots, schema.org and the
meta tags keep working.

**Hits**: keep the module and set a fixed secret instead. The auto-generated one changes with each
build, so signed image URLs break as soon as two builds or two instances serve the site.

```bash
npx nuxt-og-image generate-secret    # prints NUXT_OG_IMAGE_SECRET=<secret>
```

Set it wherever the app is built **and** wherever it runs (CI/CD variables, the deployment's
environment), because the module reads it at build time and Nitro reads it again at runtime through
`runtimeConfig.ogImage.secret`. Add the variable name without a value to `.env.example`.

Either way, copying `tests/unit/og-image-contract.test.ts` keeps the choice from drifting: it fails
when a page starts calling `defineOgImage()` while the module is off, and when the module is on and
`.env.example` documents no secret.

### 2. Give every indexable page a meta description

Indexable means every route that no `routeRules` entry marks `robots: false`. In the template that is
only `/`. Add the description in the page's `<script setup>`:

```ts
useSeoMeta({ description: 'One or two sentences about what this page offers.' });
```

`og:description` follows automatically, so do not set it twice. If the visible copy already says it,
put the text in a constant and use it in both places, as `app/pages/index.vue` does.

### 3. Only for projects created before 2.29.0: stop the doubled title

nuxt-seo-utils appends the site name to every title, including the default title, which IS the site
name. A page without its own title then reads "My Project | My Project" in the tab, in bookmarks and
in search results. Check:

```bash
grep -n "titleTemplate" app/app.vue
```

No hit means the project is affected. Copy the `useHead({ titleTemplate: … })` block, its comment and
`const siteConfig = useSiteConfig();` from the template's `app/app.vue`. The template returns
`'%s %separator %siteName'` rather than a finished string, so a separator configured in `site` still
applies.

### 4. Optional: pin the landing page head with the E2E spec

Copy `tests/e2e/landing-seo.spec.ts`. It needs no backend and no login, since it only fetches `/` and
reads the server HTML. It imports `FRONTEND_BASE` from `tests/e2e/helpers/auth-backend.ts`, which
exists since 2.21.0. In an older project, replace the import with
`process.env.NUXT_PUBLIC_SITE_URL || 'http://localhost:3001'`.

If the project's landing page has its own title, the spec still holds: it rejects only the doubled
form.

## Troubleshooting

| Symptom                                                                                            | Cause                                                                                                                                                                                   | Fix                                                                                                           |
| -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `nuxt dev` warns "OG image URLs are signed with an auto-generated secret that changes every build" | nuxt-og-image enabled without `NUXT_OG_IMAGE_SECRET`                                                                                                                                    | Step 1                                                                                                        |
| Dev console: "`defineOgImage()` is skipped as the OG Image module is not enabled."                 | A page calls `defineOgImage()` while the module is off                                                                                                                                  | Step 1, "Hits" path                                                                                           |
| Dev console on `/`: "[unhead] Page is missing a meta description and is indexable"                 | No description on an indexable page                                                                                                                                                     | Step 2                                                                                                        |
| The same warning on `/auth/*` or `/app/*`                                                          | False positive: nuxt-robots renders `noindex` on the server only, and unhead's validator checks the head on the client. The page is noindex (`x-robots-tag` header and robots meta tag) | None                                                                                                          |
| Dev console: "[unhead] twitter:card is deprecated. Use Open Graph metadata instead."               | unhead sets `twitter:card` itself and then flags it in its own validator. Dev only: the production build ships no validator to the browser and logs nothing on the server               | None. `seo: { automaticTwitterTags: false }` removes it, together with every twitter:* tag inferred from og:* |
| Tab title reads "My Project \| My Project"                                                         | `app/app.vue` predates 2.29.0 and has no titleTemplate                                                                                                                                  | Step 3                                                                                                        |
