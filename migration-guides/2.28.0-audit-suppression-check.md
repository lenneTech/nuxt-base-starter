# Migration Guide — 2.27.x → 2.28.0

Version 2.28.0 re-checks every audit suppression on each `pnpm run check`, suppresses one
dev-only advisory that has no fix (node-forge), lets users zoom the page again, type-checks
the app against the isolated build directory, and moves to `@lenne.tech/nuxt-extensions`
1.18.3. Projects created with a current `lt fullstack init` get all of it. **Existing
projects do not**: the files involved were copied when the project was created.

Nothing here breaks a working project. Step 1 matters right away if `pnpm audit` has been
red since 2026-10-01: that is the node-forge advisory, and every project with the Nuxt dev
tooling has it.

## What changed

| Area                     | Change                                                                                                                                                                                                                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Audit (node-forge)**   | GHSA-86w9-cpqp-85rv (high, node-forge `<=1.4.0`, via `listhen` in `@nuxt/cli` / `nitropack`) is suppressed in `pnpm-workspace.yaml`, with its justification. No patched release exists: npm names `>=1.4.1`, but that version is not on the registry. listhen only generates dev certificates with it; it never reaches `.output/` |
| **Suppression re-check** | New `scripts/check-suppressions.mjs`, a `check` step right after the audit. pnpm drops suppressed advisories from its report, so nothing used to say when an entry lost its reason. The step fails once a fix is installable, the advisory is withdrawn, or the package no longer resolves to a vulnerable version                 |
| **Viewport**             | `maximum-scale=1.0, user-scalable=no` removed from the viewport meta. Blocking pinch zoom fails WCAG 1.4.4; Nuxt UI fields are 16px, so iOS does not zoom into them anyway                                                                                                                                                         |
| **Type-check gate**      | `typecheck` runs `vue-tsc` against `tsconfig.check.json` (the `.nuxt-check` build dir) instead of `nuxt typecheck`, which read `.nuxt/` and failed next to a running `nuxt dev` that rewrites it                                                                                                                                   |
| **nuxt-extensions**      | 1.18.2 → 1.18.3: the auth interceptor plugin no longer triggers the `NUXT_B2007` build warning                                                                                                                                                                                                                                     |

## Upgrade steps

Paths are relative to the app (`projects/app/` in a monorepo).

### 1. Suppress the node-forge advisory

Copy the `auditConfig` block, with its comment, from the template's `pnpm-workspace.yaml`.
**In an lt monorepo it goes into the ROOT `pnpm-workspace.yaml`**: `lt` hoists `auditConfig`
there and pnpm reads it from the workspace root, so an entry in `projects/app/` would have no
effect. If the project already has an `ignoreGhsas` list, add the one entry to it.

Run step 2 before relying on it: the re-check confirms the advisory still has no fix.

### 2. Add the suppression re-check

1. Copy `scripts/check-suppressions.mjs` and `scripts/check-suppressions.d.mts` from the
   template. If the project runs the template's unit tests, copy
   `tests/unit/check-suppressions.test.ts` too.
2. Add the step to the three check chains in `package.json`, right after the audit (and
   right after the install in `check:naf`, which has no audit):

   ```diff
   - "check:raw": "… pnpm audit && pnpm peers check && …",
   + "check:raw": "… pnpm audit && node scripts/check-suppressions.mjs && pnpm peers check && …",
   ```

   and a shortcut for running it alone: `"check:suppressions": "node scripts/check-suppressions.mjs"`.

3. `scripts/check.mjs`: if the project's copy is unmodified, take the template's. Otherwise
   port its `parseSuppressionSummary` export, the `suppressions` case in `classify()`, the
   `r.suppressions = …` line next to `r.lint = …`, and the `suppressions` branch in
   `metricSuffix()`. Without them the step still runs and still fails correctly, but shows
   up as an unlabelled step without its "verified" count — and an unverified run would look
   like a plain tick.

4. CI: with a `GITHUB_TOKEN` in the environment, an entry the step could not verify fails the
   run; without one it only warns. That default is deliberate — unauthenticated, GitHub allows
   60 requests per hour per IP, and shared runners would otherwise go red on a busy day with
   nothing wrong. To make it a hard gate, expose a token: `${{ github.token }}` on GitHub
   Actions, or a CI variable holding a GitHub token without any scopes on GitLab.

### 3. Allow pinch zoom

In `nuxt.config.ts`, `app.head`:

```diff
- viewport: 'width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no',
+ viewport: 'width=device-width, initial-scale=1.0',
```

If the project lowered its input font size below 16px, iOS will zoom into focused fields
again; raise it rather than blocking zoom.

### 4. Type-check against the isolated build dir

In `package.json` (needs `tsconfig.check.json`, shipped since 2.16.0):

```diff
- "typecheck": "cross-env NUXT_BUILD_DIR=.nuxt-check nuxt typecheck",
+ "typecheck": "cross-env NUXT_BUILD_DIR=.nuxt-check nuxt prepare && vue-tsc --noEmit -p tsconfig.check.json",
```

### 5. Update nuxt-extensions

```bash
pnpm add @lenne.tech/nuxt-extensions@1.18.3
```

No code change is needed.

## Verify

```bash
pnpm run check
```

Every step green, with the new `suppressions` step reporting `1 verified` (or
`none declared` if the project suppresses nothing).
