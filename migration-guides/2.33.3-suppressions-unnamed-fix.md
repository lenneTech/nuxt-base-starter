# Migration Guide — 2.33.2 → 2.33.3

Version 2.33.3 closes a gap in both suppression guards. GitHub leaves `first_patched_version` empty on
some advisories long after a fix shipped: GHSA-86w9-cpqp-85rv (node-forge) still listed `<= 1.4.0`
with no patched version on 2026-10-28, a day after 1.4.1 and 1.4.2 were on npm. `check-suppressions.mjs`
and `check-overrides.mjs` read only that field, so a project on node-forge 1.4.0 that kept the old
suppression passed `check` for good, with the vulnerable version installed. Both guards now read the
package's version list from the registry. The release also takes `@iconify-json/lucide` 1.2.148.

Projects created with a current `lt fullstack init` get all of it. **Existing projects do not**: the
scripts were copied when the project was created. No gate enforces step 1, which is exactly the
problem it fixes: without it, a suppression can keep a fixed vulnerability installed and nothing
says so.

## What changed

| Area                   | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **check-suppressions** | Every vulnerable copy in the lockfile needs a stable release above it that lies outside every range the advisory lists (and at or above the patched version, where one is named). Deprecated releases count only when nothing else is left, as with a retired package such as node-sass. When every copy has one older than `minimumReleaseAge`, the entry fails as `FIX AVAILABLE`. A younger one passes as `fix maturing` with the time the gate clears. The gate is read from `pnpm-workspace.yaml`, default 1440 minutes (pnpm 11)                |
| **check-overrides**    | The same lookup, ported from nest-server, against the registry pnpm installs from. A fix past the gate fails as `FIX AVAILABLE` and names the version; `auditConfig.unusableFixConsumers` applies as for a named fix. A younger one prints `pending … until <time> UTC` and passes. New verdict `NOT IN TREE` (fails) when no locked version is in the range any more. An unreadable registry or lockfile is `UNVERIFIED`, which fails under `CI`. New flag `--packument-file` for offline runs: behind `--advisory-file` the registry is never asked |
| **Tests**              | `tests/unit/check-suppressions.test.ts` gains twelve cases, `tests/unit/check-overrides.guard.spec.ts` ten (fix the advisory does not name, release-age gate, a later vulnerable line, a retired package, package left the tree)                                                                                                                                                                                                                                                                                                                      |
| **Icons**              | `@iconify-json/lucide` 1.2.147 → 1.2.148                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Upgrade steps (existing project)

### 1. Copy both guards with their tests

From `nuxt-base-template/` of nuxt-base-starter 2.33.3, copy these five files unchanged:

- `scripts/check-suppressions.mjs`, `scripts/check-suppressions.d.mts`, `tests/unit/check-suppressions.test.ts`
- `scripts/check-overrides.mjs`, `tests/unit/check-overrides.guard.spec.ts`

None of them imports a sibling, and the wiring in `package.json` (`check:suppressions`,
`check:overrides`, the `check:*` chains) is unchanged. In an `lt fullstack` monorepo they go to
`projects/app/`. `check-suppressions.mjs` finds the hoisted entries in the root `pnpm-workspace.yaml`
by itself.

```bash
pnpm run check:suppressions
pnpm run check:overrides
pnpm run check
```

### 2. When a guard now fails

- **`FIX AVAILABLE`**: take the named version (raise the consumer, or an override) and delete the
  `auditConfig.ignoreGhsas` entry in the same change. It does not call for another suppression.
- **`NOT IN TREE`** / **`not-present`**: the entry hides nothing. Delete it.
- **`fix maturing`** / **`pending`**: nothing to do yet. The guard turns red by itself once the
  release-age gate clears. Do not add a `minimumReleaseAgeExclude` entry to hurry it.

### 3. Optional: lucide icons

```bash
pnpm add -D -E @iconify-json/lucide@1.2.148
```

## Troubleshooting

| Symptom                                                                         | Cause                                                        | Fix                                       |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------ | ----------------------------------------- |
| `✗ FIX AVAILABLE GHSA-… — … is published and outside the vulnerable range`      | The advisory names no fix, the registry has one              | Step 2                                    |
| `UNVERIFIED (could not reach the registry for …)`                               | Offline, or the registry blocked                             | Re-run; under `CI` this fails on purpose  |
| `typecheck:tests` fails on `createNpmPackumentFetcher` or `minimumReleaseAgeOf` | `check-suppressions.test.ts` copied without the new `.d.mts` | Copy `scripts/check-suppressions.d.mts`   |
| `check-overrides` behind `--advisory-file` reports `needs --packument-file`     | Offline runs stay offline, and that advisory names no fix    | Pass `--packument-file <packuments.json>` |
