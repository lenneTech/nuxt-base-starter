# Migration Guide — 2.35.0 → 2.35.1: vendored core lint, vue-tsc 3.3.14

Two defects in projects that `lt fullstack init` creates in vendor mode, both found by building one:

- `lint` printed three `unicorn(no-useless-spread)` warnings in `app/core/runtime/lib/sync-hints.ts` on
  every run. The template applied its `vue` and `unicorn` plugins to the vendored nuxt-extensions core,
  which nuxt-extensions itself linted with `typescript` alone up to 1.24.0.
- `typecheck` failed with six TS2339 in `app/components/Ai/ModalAiConnection.vue`. Vendoring aligns
  `vue-tsc` with nuxt-extensions, which is on 3.3.14, while the template held 3.3.13. vue-tsc 3.3.14
  stops type-checking a template at the first `//` inside a component attribute
  (vuejs/language-tools#6322, still open). It fails loudly only where the template later narrows a
  `.value`. Everywhere else the rest of the template goes unchecked and `typecheck` stays green: in
  `app/pages/index.vue`, a wrong prop next to `to="https://…"` passed.

| Project                                      | Step 1   | Step 2                            | Steps 3 and 4 |
| -------------------------------------------- | -------- | --------------------------------- | ------------- |
| npm mode                                     | required | optional, there is no `app/core/` | required      |
| vendor mode, core raised to 1.24.1 in step 1 | required | recommended                       | required      |
| vendor mode, core stays below 1.24.1         | —        | required, or the warnings stay    | required      |

A vendor-mode project may already be on vue-tsc 3.3.14 (`pnpm ls vue-tsc`). Then step 3 is urgent: its
`typecheck` can be green without checking every template.

## What changed

| Area             | Change                                                                                                                                                                                                                              |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Lint**         | `.oxlintrc.json`: `typescript` and `import` at the root, `vue` and `unicorn` in an override for everything except `app/core/**`, `import/default` and `import/namespace` off for `app/core/**`. Project code keeps all four plugins |
| **Lint test**    | `tests/unit/oxlint-vendor-core-contract.test.ts` also runs oxlint on probe files in `app/core/` and `app/utils/`, in a plain terminal and with a JetBrains terminal's `file://` paths                                               |
| **Type check**   | `vue-tsc` 3.3.13 → 3.3.14. The URLs on components in `app/pages/index.vue`, `app/layouts/default.vue` and `app/components/Ai/ModalAiConnection.vue` are constants in script, bound by name                                          |
| **Guard**        | New `tests/unit/vue-tsc-url-attributes.test.ts`: fails on every `//` in a component attribute in `app/`, `app/core/` excluded                                                                                                       |
| **Dependencies** | `@lenne.tech/nuxt-extensions` 1.24.0 → 1.24.1: `sync-hints.ts` copies with `Array.from` instead of a spread. No API change, no peer range moved. nuxt-extensions now lints itself with all four plugins and `--deny-warnings`       |

Measured with oxlint 1.90.0: `plugins` in an override only adds and never removes, so `excludeFiles` is
the only way to keep a plugin away from the core. `import` enabled in an override does not run at all,
and nothing reports that, so it stays at the root and its two rules are switched off for the core. A
1.24.0 core gives 3 warnings with the old configuration and 0 with the new one; a 1.24.1 core gives 0
with both.

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, all of it happens in `projects/app/`.

### 1. Raise nuxt-extensions

npm mode:

```bash
pnpm add -E @lenne.tech/nuxt-extensions@1.24.1
```

Vendor mode: `/lt-dev:frontend:update-nuxt-extensions-core`.

### 2. Keep the project's plugins away from the core

In `.oxlintrc.json`, set the root plugins, add the override as the first entry, and switch off the two
`import` rules in the existing `app/core/**` override:

```json
{
  "plugins": ["typescript", "import"],
  // …
  "overrides": [
    { "files": ["**/*"], "excludeFiles": ["app/core/**"], "plugins": ["vue", "unicorn"] },
    // … the project's other overrides …
    {
      "files": ["app/core/**"],
      "rules": {
        // … the rules this override already switches off …
        "import/default": "off",
        "import/namespace": "off"
      }
    }
  ]
}
```

Leave no trailing comma in the file: oxlint accepts one, but the contract test reads the file with
`JSON.parse` and fails on it. Do not move `import` into the override: it would stop running without a
word. Then copy `tests/unit/oxlint-vendor-core-contract.test.ts` from the template. The project's
current copy stays green with or without this step; the new one needs it.

```bash
pnpm run lint
pnpm run test:unit tests/unit/oxlint-vendor-core-contract.test.ts
```

### 3. Bind URLs on components from script

Copy `tests/unit/vue-tsc-url-attributes.test.ts` from the template and run it:

```bash
pnpm run test:unit tests/unit/vue-tsc-url-attributes.test.ts
```

It lists every component attribute that holds `//`, as `app/<file>:<line> <Tag attribute>`. Move each
value into `<script setup>` and bind it by name, as the template's three files do:

```vue
<script setup lang="ts">
const githubUrl = 'https://github.com/lenneTech/nuxt-base-starter';
</script>

<template>
  <UButton :to="githubUrl" target="_blank" />
</template>
```

A string literal inside the binding (`:to="'https://…'"`) is no way out. Native elements such as
`<a href="https://…">` are not affected, so the test does not list them. Never cast at the call site to
silence a TS2339 from this: the error is the only sign of the cut.

### 4. Raise vue-tsc

```bash
pnpm add -D -E vue-tsc@3.3.14
pnpm run typecheck
pnpm run typecheck:tests
```

## Check it

A green `typecheck` proves nothing here, so plant a mistake behind a URL. Add `size="xxl"` to a
component that binds one, for example `<UButton :to="githubUrl" size="xxl" />`: `pnpm run typecheck`
must fail with TS2322. Remove it again. With the URL still written into the attribute, the same mistake
passes.

Remove the guard test once a vue-tsc release fixes vuejs/language-tools#6322.
