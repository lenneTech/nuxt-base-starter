# Migration Guide — 2.26.x → 2.27.0

Version 2.27.0 makes the light-mode semantic colours pass WCAG 2.1 AA. The six tokens
`--ui-primary`, `--ui-secondary`, `--ui-success`, `--ui-info`, `--ui-warning` and
`--ui-error` now point at a darker step of their palette instead of the 500 step. Projects
created with a current `lt fullstack init` get it automatically. **Existing projects do
not**: `app/assets/css/tailwind.css` was copied when the project was created, so the change
has to be taken over by hand.

**This is a visible change.** With the starter's green, `primary-800` makes every filled
button, link and primary-coloured heading clearly darker in light mode. Dark mode is
unchanged: it keeps the 400 step, which already passes on dark surfaces.

## Why

Each token is used in three roles: as a filled surface under white text (`bg-primary`,
solid buttons), as text on white (`text-primary`), and as text on a 10% tint of itself in
Nuxt UI's `subtle` / `soft` alerts, badges and buttons. The 500 step failed AA (4.5:1) in
almost all of them: white on `primary-500` measures 2.28:1, `warning-500` as text 2.15:1.
Each new step is the lightest one that passes in all three roles.

| Token            | Before          | After           | On white / on the 10% tint |
| ---------------- | --------------- | --------------- | -------------------------- |
| `--ui-primary`   | `primary-500`   | `primary-800`   | 7.13 / 6.14                |
| `--ui-secondary` | `secondary-500` | `secondary-600` | 6.29 / 5.43                |
| `--ui-success`   | `success-500`   | `success-700`   | 5.48 / 4.78                |
| `--ui-info`      | `info-500`      | `info-700`      | 6.70 / 5.72                |
| `--ui-warning`   | `warning-500`   | `warning-800`   | 7.09 / 6.08                |
| `--ui-error`     | `error-500`     | `error-700`     | 6.47 / 5.45                |

The ratios hold for the starter's palette. A project that replaced the palette with its own
brand colours has to pick its own steps — measure them rather than copying the table.

## Upgrade steps

### 1. Update the semantic shortcuts

In `app/assets/css/tailwind.css` (`projects/app/` in a monorepo), in the light-mode block
(not in `.dark`):

```diff
-  --ui-primary: var(--ui-color-primary-500);
-  --ui-secondary: var(--ui-color-secondary-500);
-  --ui-success: var(--ui-color-success-500);
-  --ui-info: var(--ui-color-info-500);
-  --ui-warning: var(--ui-color-warning-500);
-  --ui-error: var(--ui-color-error-500);
+  --ui-primary: var(--ui-color-primary-800);
+  --ui-secondary: var(--ui-color-secondary-600);
+  --ui-success: var(--ui-color-success-700);
+  --ui-info: var(--ui-color-info-700);
+  --ui-warning: var(--ui-color-warning-800);
+  --ui-error: var(--ui-color-error-700);
```

The template also carries a comment above the block that records the measured ratios; copy
it along so the next person does not "fix" the tokens back to 500.

### 2. Check what the project built on top

Search the project for hard-coded `-500` classes that were chosen to match the old tokens
(`bg-primary-500`, `text-error-500`, …). They do not follow the tokens and keep the old,
failing contrast.

## Verify

Open a page with filled buttons and an error state in light mode and run Lighthouse's
accessibility audit (Chrome DevTools, or the `lighthouse_audit` tool of the Chrome DevTools
MCP). `color-contrast` must pass. Then run `pnpm run check`.
