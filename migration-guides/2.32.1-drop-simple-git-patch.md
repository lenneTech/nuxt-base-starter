# Migration Guide — 2.32.0 → 2.32.1

Version 2.32.1 removes the `simple-git` override and patch that 2.30.0 introduced. `@nuxt/devtools`
3.4.3 no longer depends on simple-git, so a fresh resolve contains no simple-git at all, the patch
goes unused, and pnpm stops every install with `ERR_PNPM_UNUSED_PATCH`. Until this release, every
`lt fullstack init` failed that way. The release also raises nuxt-extensions to 1.19.1 and renders
the register form's feature-dependent fields on the server.

Projects created with a current `lt fullstack init` get all of it. **Existing projects do not**: the
files involved were copied when the project was created. Step 1 becomes mandatory for them the moment
their lockfile resolves `@nuxt/devtools` 3.4.3 or later. That happens on any `pnpm update`, on a
`nuxt` bump to 4.6.2 (which requests `@nuxt/devtools ^3.4.3`), or on any resolve without a lockfile.

## What changed

| Area                | Change                                                                                                                                                                                                                                                                                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **simple-git**      | The `simple-git: 4.0.2` override, the `patchedDependencies` entry and `patches/simple-git@4.0.2.patch` are gone. The lockfile resolves `@nuxt/devtools` 3.4.4, which has no simple-git dependency, so the four advisories 2.30.0 closed stay closed. The template ships no `patches/` directory any more                                           |
| **nuxt-extensions** | 1.19.0 → 1.19.1: without `NUXT_API_URL` / `NUXT_PUBLIC_API_URL` the server no longer fetches its own `/system-setup/status` in an endless loop (the first request ended in a heap out-of-memory crash). `fetchWithAuth` retries once with a fresh JWT after a 401 caused by an expired bearer; in JWT mode that needs nest-server 11.43.1 or later |
| **Register page**   | `app/pages/auth/register.vue` fetches the auth feature flags during SSR, so the terms checkbox (`signUpChecks`) is in the server HTML. The production build logged a hydration mismatch on every visit before. With sign-up disabled, the redirect to `/auth/login` stays on the client, so its toast still arrives                                |
| **E2E**             | `tests/e2e/register-ssr-features.spec.ts` pins both. `tests/e2e/helpers/auth-backend.ts` gains `releaseSystemSetupClaim()`, which removes the setup claim a successful `POST /system-setup/init` leaves behind, so a spec that sets up the system and deletes its admin can run again within five minutes                                          |

## Upgrade steps (existing project)

### 1. Remove the simple-git override, its patch entry and the patch file together

Standalone app: in `pnpm-workspace.yaml`, delete the `'simple-git': 4.0.2` entry under `overrides:`
and the whole `patchedDependencies:` block (if simple-git was its only entry), then delete
`patches/simple-git@4.0.2.patch`. In an `lt fullstack` monorepo the three live at the ROOT:
`<root>/pnpm-workspace.yaml` and `<root>/patches/`.

Then move devtools off the line that still pulls simple-git 3, and check the result:

```bash
pnpm update @nuxt/devtools
pnpm why -r simple-git    # must print nothing
pnpm audit
```

All three go in one change, and the devtools update belongs to it. Removing only the override while
the lockfile still holds `@nuxt/devtools` 3.4.2 brings back simple-git 3.36.0 with two critical and
two high advisories. Keeping the patch after devtools moved is what fails the install.

Leave the Dockerfile line that copies `patches/` in place. It skips a missing directory
(`[ ! -d /tmp/src/patches ] || …`) and is what a future patch needs.

### 2. Raise nuxt-extensions to 1.19.1

npm mode:

```bash
pnpm add @lenne.tech/nuxt-extensions@1.19.1
```

Vendor mode: update the vendored core with `/lt-dev:frontend:update-nuxt-extensions-core`.

The out-of-memory fix matters wherever a server can start without an API URL: a misconfigured stage,
a container started by hand. The JWT retry only takes effect against nest-server 11.43.1 or later.
From 11.10.3 up to and including 11.43.0, nest-server rejects every bearer JWT once `BASE_URL` is set,
the freshly minted one included.

### 3. Optional: the register page and its spec

Copy the `if (import.meta.server) { await fetchFeatures(); }` block and the `import.meta.server`
guard in the `signUpEnabled` watcher from `app/pages/auth/register.vue`. Take both halves: the SSR
fetch without the guard turns the disabled-sign-up redirect into a bare server 302, and its toast never
reaches the browser.

For the tests, copy `tests/e2e/register-ssr-features.spec.ts` and `releaseSystemSetupClaim()` from
`tests/e2e/helpers/auth-backend.ts`. The second test of the spec only runs against a backend with
sign-up disabled (`betterAuth.emailAndPassword.disableSignUp`) and is skipped otherwise.

## Troubleshooting

| Symptom                                                                | Cause                                                                      | Fix                            |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------ |
| `pnpm install` fails with `ERR_PNPM_UNUSED_PATCH` for simple-git@4.0.2 | `@nuxt/devtools` 3.4.3+ resolves no simple-git, so the patch has no target | Step 1                         |
| `pnpm audit` reports simple-git 3.36.0 after step 1                    | The override went, but `@nuxt/devtools` is still 3.4.2                     | `pnpm update @nuxt/devtools`   |
| The server dies of heap out-of-memory on its first request             | No API URL set, nuxt-extensions older than 1.19.1                          | Step 2, and set `NUXT_API_URL` |
| `/auth/register` logs a hydration mismatch in the production build     | Feature flags fetched on the client only                                   | Step 3                         |
