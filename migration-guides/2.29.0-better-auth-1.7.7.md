# Migration Guide — 2.28.x → 2.29.0

Version 2.29.0 is a security release. It pins better-auth to 1.7.7, moves to
`@lenne.tech/nuxt-extensions` 1.18.4, suppresses one dev-only advisory that has no fix (braces),
and localizes Nuxt UI's own texts. Projects created with a current `lt fullstack init` get all of
it. **Existing projects do not**: the files involved were copied when the project was created.

**Step 1 is urgent.** better-auth below 1.7.7 is affected by
[GHSA-965c-763c-88jm](https://github.com/better-auth/better-auth/security/advisories/GHSA-965c-763c-88jm)
(critical): the OAuth state can be used as a magic link to sign in as another user. The flaw is
in better-auth's **server** end, so the API is what has to move. Updating only the app closes
nothing.

| **better-auth**     | `better-auth` and `@better-auth/passkey` pinned to `1.7.7` (were `1.7.1`). Lock-step with `@lenne.tech/nest-server` 11.41.8 and `@lenne.tech/nuxt-extensions` 1.18.4, which both declare `>=1.7.7 <1.8.0`                                                                        |
| **nuxt-extensions** | 1.18.3 → 1.18.4: peer range only, no code or API change                                                                                                                                                                                                                          |
| **Audit (braces)**  | GHSA-vfj7-8cjw-p6xm (high, braces `<=3.0.3`, via nitropack's build-time globbing) is suppressed in `pnpm-workspace.yaml`, with its justification. No patched release exists. `check-suppressions` re-verifies it on every `check`                                                |
| **Nuxt UI locale**  | `UApp` gets `:locale="de"` in `app.vue` and `error.vue`, so Nuxt UI's own texts ("Passwort anzeigen", "Zurück zur Startseite") are German                                                                                                                                        |
| **Toasts**          | Screen readers announce toasts as "Benachrichtigung" instead of "Notification" (`toaster.label` in `app.config.ts`)                                                                                                                                                              |
| **Page title**      | A page without its own title no longer reads "Name \| Name"                                                                                                                                                                                                                      |
| **Contrast**        | Field descriptions and inactive tabs pass WCAG AA (were 2.56:1 and 4.34:1)                                                                                                                                                                                                       |
| **Dependencies**    | `@nuxt/ui` 4.11.3 (with reka-ui 2.10.5), vitest 5.0.3 (admitted by better-auth 1.7.7's peer range), `@nuxt/test-utils` 4.3.3, oxlint 1.86.0, oxfmt 0.71.0, vue-tsc 3.3.12; the lockfile was re-resolved, which also moves the `@tiptap/*` family to 3.31.4 and `unhead` to 3.4.2 |

## Upgrade steps

Paths are relative to the app (`projects/app/` in a monorepo).

### 1. better-auth 1.7.7 on both ends

1. **API first:** update `@lenne.tech/nest-server` to 11.41.8 (see its migration guide). It runs on
   better-auth 1.7.7 and detects the installed line at runtime, so api and app can move in one go.
2. **App:**

   ```bash
   pnpm add @lenne.tech/nuxt-extensions@1.18.4 better-auth@1.7.7
   pnpm add @better-auth/passkey@1.7.7   # only if the project uses passkeys
   ```

3. **Monorepo:** pin both in the ROOT `pnpm-workspace.yaml`, so api and app cannot resolve
   different versions:

   ```yaml
   overrides:
     better-auth: 1.7.7
     '@better-auth/passkey': 1.7.7
   ```

Verify with `pnpm why better-auth` from the workspace root: every line must read 1.7.7.

**Do not read a clean audit as "not affected".** As of 2026-10-03 the advisory is listed only on
better-auth's repository, not yet in the global GitHub Advisory Database, so `pnpm audit` does
not report it.

### 2. Suppress the braces advisory

`pnpm audit` has been red since 2026-10-03 in every project with the Nuxt build tooling. Copy the
`GHSA-vfj7-8cjw-p6xm` entry, with its comment, from the template's `pnpm-workspace.yaml` into the
project's `auditConfig.ignoreGhsas`. **In an lt monorepo it goes into the ROOT
`pnpm-workspace.yaml`**, where `lt` hoists `auditConfig`. Projects that took the 2.28.0 guide run
`check-suppressions`, which confirms the advisory still has no fix.

### 3. Nuxt UI in German (optional, recommended for German UIs)

In `app/app.vue` and `app/error.vue`:

```diff
+ import { de } from '@nuxt/ui/locale';
  …
- <UApp :toaster="appConfig.toaster">
+ <UApp :locale="de" :toaster="appConfig.toaster">
```

`error.vue` replaces `app.vue` on an error, so it needs the props too. In `app/app.config.ts`,
add `label: 'Benachrichtigung'` to `toaster`. The title template and the contrast fixes are in
the same two files of the template; take them if the project kept the template's defaults.

**Run the E2E suite after this step: the locale can make selectors ambiguous.** Nuxt UI's own
controls now carry German accessible names: the toast's close button is „Schließen“, the
password toggle „Passwort anzeigen“. A project with its own button of the same name gets two
matches, and Playwright's strict mode rejects a locator such as
`getByRole('button', { name: 'Schließen', exact: true })`. Observed in a project whose panel had
its own „Schließen“ button next to an open toast. Scope the locator to its container
(`panel.getByRole(…)`) rather than adding `.first()`, which only picks whichever match comes
first in the DOM. The template's own tests are not affected.

`toaster.label` changes the word announced before each toast, not the name of the toast region:
that one stays „Notifications (F8)“, because it belongs to Reka's `ToastViewport`, which Nuxt UI
(4.11.3) does not pass a label to.

### 4. Dependency refresh (optional)

Take the versions from the template's `package.json` if the project still matches it. vitest
4 → 5 needed no test or config change in the template; `@nuxt/test-utils` 4.3.3 rewrites the
version line in `.nuxtrc`, which is expected. Nothing else here asks for code changes.

## Verify

```bash
pnpm run check
```

Every step green, with the `suppressions` step reporting `2 verified`.
