# Migration Guide: 4.0.7 — `check` survives a taken port, `NUXT_PUBLIC_STORAGE_PREFIX` goes

Two changes to the project's tooling and configuration. Neither touches the app's runtime.

**`scripts/check-server-start.mjs` starts again after `EADDRINUSE`.** The last step of `check` binds a
free port, releases it and starts the built server on it. The port is free at that moment, not reserved:
when another process (a second `check`, a dev server, a test runner) binds it first, the server dies
with `listen EADDRINUSE` and `check` went red for a reason that has nothing to do with the project. Since
4.0.7 the script starts the server again on newly allocated ports, up to three times, and says why
(`Port … was taken before the server bound it (EADDRINUSE), attempt 1 of 3`). Only `EADDRINUSE` before
the server is up counts; any other early exit fails at once, as before.

**`NUXT_PUBLIC_STORAGE_PREFIX` is gone from `.env.example` and the docs.** It promised a localStorage
namespace per project, but nothing reads it: no `runtimeConfig.public` key receives it, and neither the
template nor nuxt-extensions has a storage namespace. Browser storage is per origin anyway, and
`lt dev up` gives every project an origin of its own. (The Angular starter's `NG_PUBLIC_STORAGE_PREFIX`
is a different case: ng-base's `LtStorageService` reads it.)

| Project                                                     | What to do       |
| ----------------------------------------------------------- | ---------------- |
| Runs `check` next to other servers or checks on one machine | Step 1           |
| Carries `NUXT_PUBLIC_STORAGE_PREFIX` in `.env.example`      | Step 2, optional |

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, the steps happen in `projects/app/`.

### 1. `scripts/check-server-start.mjs`

Take over `scripts/check-server-start.mjs` and `scripts/check-server-start.d.mts` from the starter, if
yours are the starter's. The options and the CLI arguments are unchanged; `NUXT_DEFAULTS` gains
`portAttempts: 3`, and the module exports `isPortTakenOutput()`.

The tests come with it: `tests/unit/check-server-start.test.ts` and the two fixtures
`tests/unit/fixtures/server-start/port-taken-once.mjs` and `port-always-taken.mjs`. The old test file
stays green with the new script, so they are optional.

### 2. Optional: `NUXT_PUBLIC_STORAGE_PREFIX`

Delete the variable and its comment from `.env.example` (and from `.env`, where it does nothing either).
Two tests of the starter read `.env.example` and have to move with it:

- `tests/unit/lt-dev-env.test.ts`: the test "documents NUXT_PUBLIC_STORAGE_PREFIX" fails once the line
  is gone. Delete it, or take over the 4.0.7 file, which checks the opposite.
- `tests/unit/runtime-config-contract.test.ts`: remove the `NUXT_PUBLIC_STORAGE_PREFIX` entry from
  `MODULE_OWNED`. It claimed nuxt-extensions owns the key, which it does not.

Keep the line as long as your project reads the variable itself.

## Check it

```bash
pnpm run check
```
