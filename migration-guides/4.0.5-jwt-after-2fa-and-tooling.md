# Migration Guide: 4.0.5 — nuxt-extensions 4.0.5, Nuxt UI 4.13.1 and tooling

The template moves to `@lenne.tech/nuxt-extensions` 4.0.5. That release asks nothing of a project.
It matters in the JWT mode, an API with `cookies: false`. Since nest-server 12.11.0 a JWT is bound to
its session, and switching 2FA on or off replaces the session:

- `useLtAuthClient().twoFactor.verifyTotp`, `verifyBackupCode`, `enable`, `disable` and
  `changePassword` now store the JWT the API sends with the answer.
- `setUser(user)` without a mode keeps the JWT mode while it updates the same user.

Measured against nest-server 12.11.1 in the JWT mode: with nuxt-extensions 4.0.4 the JWT the app held
after switching 2FA on no longer authenticated, while with 4.0.5 it did. For switching 2FA off the API
needs nest-server 12.11.1, because 12.11.0 sends no new JWT there. The template's `security.vue`
needs no change. The cookie mode, the template's default, behaves as before.

| Project                                              | What to do                          |
| ---------------------------------------------------- | ----------------------------------- |
| Every project                                        | Steps 1 and 2                       |
| API runs in the JWT mode (`cookies: false`)          | Also the API on nest-server 12.11.1 |
| Carries a copy of `tests/e2e/auth-lifecycle.spec.ts` | Step 3, optional                    |

Unchanged on purpose, for the reasons in the
[4.0.4 guide](./4.0.4-nuxt-ui-and-tooling.md):

- better-auth and `@better-auth/passkey` stay on 1.7.19, in step with nest-server-starter 12.11.1.
- TypeScript stays on 6.0.3.
- `@vueuse/nuxt` stays on 14.4.0: `@nuxt/ui` 4.13.1 still requires `@vueuse/core` ^14.4.0.

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, `pnpm add` runs in `projects/app/`. The `overrides` live in the root
`pnpm-workspace.yaml`.

### 1. nuxt-extensions and Nuxt UI

```bash
pnpm add -E @lenne.tech/nuxt-extensions@4.0.5 @nuxt/ui@4.13.1
```

If the project carries the `'@nuxt/ui@<4.8.1'` override, raise its target to `4.13.1` in the same
change; with a different target the tree holds two copies of `@nuxt/ui`. 4.13.1 still pins reka-ui
2.11.0, so the reka-ui patch from starter 2.33.1 keeps applying.

Nuxt UI 4.13.1 only fixes bugs. One fix changes the markup a test may assert on: menu and sidebar
toggles carry `aria-expanded` (nuxt/ui#7457).

### 2. Tooling

```bash
pnpm add -E -D oxlint@1.95.0 oxfmt@0.80.0 @nuxtjs/seo@6.1.0
pnpm dedupe
pnpm run format && pnpm run lint
```

In the template neither oxlint 1.95.0 nor oxfmt 0.80.0 changed a file or reported a finding.

`@nuxtjs/seo` 6.1.0 serves the sitemap as plain XML, without the built-in stylesheet. To keep it, set
`sitemap: { xsl: true }` in `nuxt.config.ts`. A project that pins one of the bundled modules itself
(`@nuxtjs/sitemap`, `nuxt-og-image`, `@nuxtjs/robots`, …) raises it to the new minimum or drops the
pin. The template pins none.

### 3. Optional: the session check after 2FA

`tests/e2e/auth-lifecycle.spec.ts` in the template checks after steps 4 and 7 (2FA on, 2FA off) that
the app is still signed in, asked the way the app asks. In the JWT mode
(`E2E_EXPECT_AUTH_MODE=jwt`) the spec sends only the bearer from the app's token cookie
(`lt-jwt-token` by default), from Playwright's `request` fixture without the browser's cookies. In
the cookie mode it sends the session cookie.
To take the check over:

1. Copy `expectSessionAsTheAppAsks()` and the two calls.
2. Add `APIRequestContext` to the type import from `@playwright/test`. Without it
   `typecheck:tests` fails with `TS2304`.
3. Add `request` to the parameters of both tests.

In the JWT mode the check needs nuxt-extensions 4.0.5 and nest-server 12.11.1:

- With nuxt-extensions 4.0.4, step 4 fails.
- Against nest-server 12.11.0, step 7 fails.

A request through `page.request` would not catch either failure, because the forwarded Better-Auth
routes set a session cookie in the JWT mode too. `docs/e2e-auth.md`, scenario 3, has the details.
