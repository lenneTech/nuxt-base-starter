# Migration Guide: 4.0.3 — nuxt-extensions 4.0.3, icon endpoint, tooling and route guards

The template moves to `@lenne.tech/nuxt-extensions` 4.0.3 and `@nuxt/ui` 4.12.2. nuxt-extensions
4.0.3 asks nothing of a project: it adds `signIn.social` to `useLtAuth()` and the auth client, and it
leaves a `data:` profile photo out of the `lt-auth-state` cookie (`user.image` is then `undefined`).

The change that needs care is the `@iconify/vue` override from starter 2.33.4 (guide
`2.33.4-glob-minimatch-majors.md`, step 5). `@nuxt/icon` 2.6.3 treats any Iconify API host as the
default provider (nuxt/icon#574, fixing #571), so the app's `/_nuxt_icon` endpoint is installed again
with `@iconify/vue` 5.0.5, and the template drops the hold. Removing the entry alone is not enough:
measured on a project lockfile, `pnpm install` then keeps `@nuxt/icon` 2.6.2 and takes
`@iconify/vue` 5.0.5, which is the pair that sends the browser to `api.iconify.design`. Step 2 lifts
both.

| Project                                                           | What to do          |
| ----------------------------------------------------------------- | ------------------- |
| Carries `'@iconify/vue': 5.0.4` under `overrides`                 | Steps 1 and 2       |
| Carries `'readdir-glob>minimatch@<11.0.1'`                        | Also step 3         |
| Runs Playwright in CI with `mcr.microsoft.com/playwright` (image) | Also step 4         |
| Has the template's route guards (`app/middleware/*.global.ts`)    | Also step 5         |
| None of these                                                     | Step 1, if you like |

Unchanged on purpose: better-auth and `@better-auth/passkey` stay on 1.7.19, in step with the API.
TypeScript stays on 6.0.3 (vue-tsc cannot drive TypeScript 7) and `@vueuse/nuxt` on 14.4.0
(`@nuxt/ui` 4.12.2 still requires `@vueuse/core` 14).

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, `pnpm add` and `pnpm update` run in `projects/app/`. The `overrides`
live in the root `pnpm-workspace.yaml`, where `lt` hoisted them.

### 1. nuxt-extensions and Nuxt UI

```bash
pnpm add -E @lenne.tech/nuxt-extensions@4.0.3 @nuxt/ui@4.12.2
```

If the project carries the `'@nuxt/ui@<4.8.1'` override, raise its target to `4.12.2` in the same
change. It also lifts `@lenne.tech/bug.lt`'s pinned `@nuxt/ui` 4.2.1, and with a different target the
tree holds two copies of `@nuxt/ui`.

### 2. Drop the `@iconify/vue` hold

Delete `'@iconify/vue': 5.0.4` from `overrides`, together with the comment above it, then lift
`@nuxt/icon`:

```bash
pnpm install
pnpm update --depth Infinity @nuxt/icon
pnpm why @nuxt/icon @iconify/vue    # one copy each: @nuxt/icon 2.6.3, @iconify/vue 5.0.5
```

Run the update after removing the entry, not before: with the entry still in place it pins
`@iconify/vue` 5.0.4 below the `^5.0.5` that `@nuxt/icon` 2.6.3 requests.

Measured with pnpm 11.28.12. If `pnpm why` still shows `@nuxt/icon` 2.6.2 (pnpm 11.28.8 left a
locked transitive version in place in an earlier measurement), lift it with a temporary override: add
`'@nuxt/icon': 2.6.3` under `overrides`, `pnpm install`, remove the line again, `pnpm install`. The
lockfile keeps 2.6.3. The same works for minimatch in step 3.

### 3. Optional: readdir-glob's minimatch

The template raises the target of `'readdir-glob>minimatch@<11.0.1'` from 11.0.8 to 11.0.9, because a
fresh resolve gives glob's minimatch 11.0.9. Raise it together with the rest of the tree, or the
project holds both versions:

```bash
pnpm install
pnpm update --depth Infinity minimatch
pnpm why minimatch                   # 11.0.9 only
```

### 4. Tooling

```bash
pnpm add -E -D @playwright/test@1.65.1 vitest@5.1.1 oxlint@1.94.0 oxlint-tsgolint@7.0.2007 oxfmt@0.79.0 lint-staged@17.6.1 @iconify-json/lucide@1.2.156
```

Take `oxlint-tsgolint` with it: oxlint 1.94.0 requires 7.0.2007 or later, and a project on 4.0.2 has
7.0.2006. Linting still runs with the older one, but `pnpm peers check`, part of `check`, fails with
`unmet peer oxlint-tsgolint`.

The Playwright image in CI has to match `@playwright/test`: raise every
`mcr.microsoft.com/playwright:v1.65.0-noble` in `.gitlab-ci.yml` and `.github/workflows/*.yml` to
`v1.65.1-noble`. In an `lt fullstack` monorepo `pnpm run check:playwright-image` compares the two
and fails while they differ.

### 5. Route guards read the auth cookie as the library does

`auth.global`, `guest.global` and `admin.global` parsed the `lt-auth-state` cookie themselves: under
`cookieNames.state` or `lt-auth-state`, and from the first cookie of that name only. nuxt-extensions
names the cookie `<prefix>-auth-state` when `NUXT_PUBLIC_COOKIE_PREFIX` is set, and of two cookies
with that name it takes the one with a user (a deployment can hold a host-only and a domain-scoped
twin). With a prefix, the guards sent every signed-in user to the login page; with a user-less twin
in front, some of them.

Copy `app/utils/auth-state-user.ts` and the three files under `app/middleware/` from the template,
together with `tests/unit/utils/auth-state-user.test.ts` and `tests/unit/middleware/auth-guards.test.ts`.
A project that changed its guards keeps its logic and replaces only the cookie read with
`readAuthStateUser()`. Do not use `useLtAuth()` there: in a route middleware its `useCookie` calls
leave a cookie listener behind on every navigation.

## Check it

```bash
pnpm audit                                                    # No known vulnerabilities found
pnpm exec vitest run tests/unit/icon-endpoint-contract.test.ts
pnpm run check
```

The icon test (since 2.33.4) runs the code of the installed `@nuxt/icon` and `@iconify/vue` and
fails while the browser would use Iconify's public API. Without the test, sign in and watch the
network panel: icons load from `/_nuxt_icon`, none from `api.iconify.design`.
