# Migration Guide — 2.29.x → 2.30.0

Version 2.30.0 closes four `simple-git` advisories (two critical) with an override plus a small pnpm
patch, adds the `check:overrides` guard from nest-server to the `check` chain, and gives the header
link its site name as accessible label. Projects created with a current `lt fullstack init` get all
of it. **Existing projects do not**: the files involved were copied when the project was created.

**Read step 1 before copying the patch.** The patch is the first one this template ships, and an
older Dockerfile that does not copy `patches/` breaks the image build as soon as it arrives.

## What changed

| Area                        | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **simple-git (security)**   | Override `simple-git` → `4.0.2`, which closes GHSA-x6jw-m9v5-85vh and GHSA-v5rq-49vh-5v5c (critical) and GHSA-g4wm-2vf7-vfgr and GHSA-858h-whjf-mvg5 (high). The path is `nuxt > @nuxt/devtools`, so dev tooling only; no fixed 3.x exists. `patches/simple-git@4.0.2.patch` (wired through `patchedDependencies`) restores the ESM default export simple-git 4 dropped and `@nuxt/devtools` imports. It re-exports the existing factory and changes no behaviour |
| **postcss-selector-parser** | Override to `7.1.6` (GHSA-rj75-hqrm-r3gf, moderate)                                                                                                                                                                                                                                                                                                                                                                                                               |
| **check:overrides**         | `scripts/check-overrides.mjs` runs after `check-suppressions` in `check:raw`, `check:fix` and `check:naf`. A run without a usable audit shows as "NOT verified", never as a tick                                                                                            |

## Upgrade steps (existing project)

### 1. Make sure every Dockerfile copies `patches/` before `pnpm install`

`patchedDependencies` makes a patch file part of dependency resolution: `pnpm install --frozen-lockfile`
hashes each one before installing anything and stops with
`ENOENT: no such file or directory, open '/app/patches/simple-git@4.0.2.patch'` when one is missing.
A full local `check` passes regardless, because the file is in the working tree. The failure appears
only in the Docker build, typically in CI or on deploy.

Current templates copy the directory already. Check your own Dockerfiles for an equivalent of these
lines in the stage that runs `pnpm install`:

```dockerfile
# nuxt-base-template/Dockerfile (app)
&& { [ ! -d /tmp/src/patches ] || cp -rf /tmp/src/patches /app/; } \

# nest-server-starter/Dockerfile (api)
[ ! -d /tmp/src/patches ] || cp -rf /tmp/src/patches /app/; \
```

**In an `lt fullstack` monorepo check BOTH images.** The patch lives in the root
`pnpm-workspace.yaml`, so the API image's install needs the file too, although the patch is for an
app dependency. A project generated from an older starter may lack the line in either Dockerfile.

### 2. Update the lt CLI before running `lt fullstack init` or adding an app

```bash
npm i -g @lenne.tech/cli@latest   # 1.50.4 or newer
```

pnpm reads `patchedDependencies` only from the workspace root. From 1.50.4 the CLI hoists the entry
together with the override and moves the patch file to `<root>/patches/`. Older CLIs drop the entry,
and the first `pnpm install` of the new project fails in `nuxt prepare` with
`The requested module 'simple-git' does not provide an export named 'default'`.

### 3. Take over the override and the patch

Standalone app: copy the `simple-git` and `postcss-selector-parser` entries under `overrides:`, the
`patchedDependencies` block from `nuxt-base-template/pnpm-workspace.yaml`, and the file
`nuxt-base-template/patches/simple-git@4.0.2.patch`. Then:

```bash
pnpm install
pnpm audit
```

In a monorepo, put the same entries into the ROOT `pnpm-workspace.yaml` and the patch into
`<root>/patches/`.

Keep the override and the patch together. The patch is pinned to exactly 4.0.2, so any other
simple-git version makes `pnpm install` fail loudly rather than patch the wrong code. The two leave at
different times: delete the patch (and its `patchedDependencies` entry) once `@nuxt/devtools` imports
`{ simpleGit }`, but the override only once nuxt requests a `@nuxt/devtools` that no longer depends on
simple-git 3. simple-git 3.36.0 already has the named export, so a devtools release that switches to it
can still ask for the vulnerable 3.x line.

### 4. Optional: adopt the `check:overrides` guard

Copy `nuxt-base-template/scripts/check-overrides.mjs` and its spec
`tests/unit/check-overrides.guard.spec.ts`, add `"check:overrides": "node scripts/check-overrides.mjs"`,
and insert `node scripts/check-overrides.mjs` after `node scripts/check-suppressions.mjs` in
`check:raw`, `check:fix` and `check:naf`. Inside a monorepo the copy in `projects/app` finds nothing
to check, because the CLI hoists the overrides to the root. There the root's own guard (lt-monorepo)
covers them.

### 5. Optional: the header label

In `app/layouts/default.vue`, add `const siteConfig = useSiteConfig();` and
`:title="siteConfig.name"` on `UHeader`.

## Troubleshooting

| Symptom                                                                                                     | Cause                                                                                 | Fix                                                                                           |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Docker build: `ENOENT … /app/patches/simple-git@4.0.2.patch`                                                | The Dockerfile copies no `patches/` before `pnpm install`                             | Step 1                                                                                        |
| First `pnpm install` of a new project fails in `nuxt prepare`: `does not provide an export named 'default'` | An lt CLI older than 1.50.4 dropped `patchedDependencies` while hoisting the override | Step 2, then re-create the project or add the entry to the root `pnpm-workspace.yaml` by hand |
| `pnpm install` fails with `ERR_PNPM_UNUSED_PATCH`                                                           | simple-git resolved to a version other than 4.0.2                                     | Keep the override at exactly `4.0.2` next to the patch                                        |
| `check` shows overrides as "NOT verified"                                                                   | The audit could not reach the registry                                                | Re-run with network access; suppressions are still checked                                    |
