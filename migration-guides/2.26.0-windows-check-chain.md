# Migration Guide — 2.25.x → 2.26.0

Version 2.26.0 makes the `check` chain run on Windows, loads the oxlint config that was
silently ignored until now, hardens the watchdog's process kill, fixes the page language
(`<html lang="en">` on a German UI), removes 13 security overrides that a fresh resolve no
longer needs, and moves to `@lenne.tech/nuxt-extensions` 1.18.2. Projects created with a
current `lt fullstack init` get all of it.
**Existing projects keep working on macOS and Linux**, but any project that kept the
template's `lang: 'de'` without a `site.defaultLocale` serves the wrong page language — take
step 6 regardless. The other steps matter if the project has to
run `pnpm run check` on Windows, or to pick up the lint and override fixes.

`lt fullstack update` (lt CLI 1.47.0 or newer) does part of this for you: it refreshes the
monorepo's root check wrapper, and in `projects/app/` it removes `--fix-suggestions` /
`--fix-dangerously` from `package.json`, the lint-staged config and `scripts/check.mjs`, then
renames `oxlint.json` to `.oxlintrc.json`. It edits only tracked files without uncommitted
changes and names every file it skipped. Everything else below is copied by hand.

## What changed

| Area                  | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Server-start step** | `scripts/check-server-start.sh` (bash) is replaced by `scripts/check-server-start.mjs` (Node built-ins only). Under `cmd.exe`, `bash` is missing or resolves to the WSL launcher, so every check chain died at its last step                                                                                                                                                                                                                                                 |
| **Watchdog kill**     | `scripts/check.mjs` kills a wedged step's tree with `taskkill /PID <pid> /T /F` on Windows, and refuses any pid that is not a process it spawned (`undefined`, `0`, `1`, `-1`, and Windows' 0 and 4)                                                                                                                                                                                                                                                                         |
| **Test safety**       | New vitest setup file `tests/unit/support/signal-guard.setup.ts` (guard logic in `signal-guard.ts`): a unit test may only send a real signal to a process it spawned                                                                                                                                                                                                                                                                                                         |
| **Line endings**      | New `.gitattributes` pins LF for every text file (CRLF only for `.cmd` / `.bat`). Git for Windows defaults to `core.autocrlf=true`, which breaks shell scripts, hooks and the format check                                                                                                                                                                                                                                                                                   |
| **Windows CI**        | A non-blocking Windows job runs the CI placement check, the repo script tests and the template's format, lint and unit tests — all green as of 2.26.0. Audit, build, typecheck and the server-start step are not run there yet, so on Windows they are fixed by design but not verified by CI                                                                                                                                                                                |
| **Lint config**       | `oxlint.json` → `.oxlintrc.json`. oxlint only discovers the dotted name, so every rule in the old file was ignored. `scripts/**` gets `no-console: off` — console output is what those CLIs are for                                                                                                                                                                                                                                                                          |
| **Lint auto-fix**     | `--fix-suggestions` is gone from `lint:fix` and from the fix mode of `scripts/check.mjs`. oxlint marks suggestions as possibly behaviour-changing, and the `no-console` one deletes every console call — including the check report                                                                                                                                                                                                                                          |
| **Overrides**         | 13 entries removed (`sharp`, `svgo`, `minimatch`, `tar`, `postcss`, `brace-expansion`, `nanoid`, `shell-quote`, `fast-xml-parser`, `postcss-selector-parser`, `browserslist`, `@tiptap/core`, `@tiptap/pm`). Four remain                                                                                                                                                                                                                                                     |
| **Lockfile**          | Re-resolved from scratch, so the template now tests the tree a generated project actually installs                                                                                                                                                                                                                                                                                                                                                                           |
| **Site locale**       | `site.defaultLocale: 'de'` in `nuxt.config.ts`. Without it nuxt-seo-utils rendered `<html lang="en">` over the `lang: 'de'` in `app.head` — wrong screen-reader voice, and og:locale, canonical casing and Schema.org in English                                                                                                                                                                                                                                             |
| **Dependencies**      | `@lenne.tech/nuxt-extensions` 1.18.1 → 1.18.2: `validateSession()` no longer hangs a server render, the auth client uses `NUXT_API_URL` during SSR, and `gotoAndWaitForHydration` survives a page that navigates away on its own. Also `@nuxt/ui` 4.11.2, `vue` 3.5.43, `valibot` 1.5.0, `@nuxt/test-utils` 4.3.2, oxlint 1.85.0 / oxfmt 0.70.0 and patch updates. The `@nuxt/ui` override key widens to `<4.8.1` (GHSA-gj2h-2fpw-fhv9 was widened), `unhead` moves to 3.4.1 |

## Upgrade steps

### 1. Port the server-start step (Windows only)

Copy `scripts/check-server-start.mjs` and `scripts/check-server-start.d.mts` from the 2.26.0
template into `projects/app/scripts/` and delete `check-server-start.sh`. Then replace the
call in the three chains and in CI:

```diff
-  "check:raw": "… && pnpm run typecheck:tests && bash scripts/check-server-start.sh",
+  "check:raw": "… && pnpm run typecheck:tests && node scripts/check-server-start.mjs",
```

Same for `check:fix`, `check:naf`, and every CI step that ran the `.sh`. Behaviour is
unchanged: free port via `listen(0)`, `NUXT_API_URL` pointed at a closed port so SSR
fetches fail fast, `GET /` must answer 2xx/3xx, the server is always stopped. The Nuxt
defaults are built in; no arguments are needed.

### 2. Update the check wrapper

Copy `scripts/check.mjs` and `scripts/check.d.mts` from the template. If the project changed
its copy, port three things by hand: the `isKillablePid` / `killTreePlan` / `killTreeWith` /
`pgrepChildren` / `killTree` block, the `node:child_process` import (the block needs
`execFileSync`; a 2.25.x copy imports only `execSync` and `spawn`, and without it the tree kill
fails silently inside its own try/catch), and the lint fix command in `toFixCommand`
(`oxlint --fix`, no `--fix-suggestions` — already stripped if `lt fullstack update` ran).

Then update the export pin in `tests/unit/check-cli-entry.test.ts`, or copy the test from the
template. The new module exports three more helpers, and the 2.25.x test still expects
`'buildGroups'` alone, so `pnpm run check` (and the pre-push hook) goes red until it reads:

```ts
expect(result.stdout).toBe('buildGroups,isKillablePid,killTreePlan,killTreeWith');
```

Copy `tests/unit/check-kill-tree.test.ts` along with it — it covers the new block.

### 3. Arm the signal guard

Copy `tests/unit/support/signal-guard.ts`, `signal-guard.setup.ts` and `signal-guard.test.ts`
and register the **setup** file:

```ts
// vitest.config.ts
setupFiles: ['tests/unit/setup.ts', 'tests/unit/support/signal-guard.setup.ts'],
```

Probes with signal 0 stay allowed. A test that signals a pid it did not spawn now fails.

Never write a test that sends a real `process.kill(-1, …)`, `0`, `1` or a foreign pid on the
assumption that the guard refuses it. Without the guard — a config merge that drops the
entry, a mutation run — that call is the kill(2) broadcast to every process of the user, and
it has rebooted a developer machine twice. The guard's own test uses the probe pid `2 ** 30`,
which no system hands out, so it can only fail with ESRCH when the guard is missing.

### 4. Line endings

Copy `.gitattributes` into `projects/app/` (the lt-monorepo root carries its own). On an
existing clone, renormalise once and commit the result:

```bash
git add --renormalize . && git status
```

### 5. Load the lint config

Skip the rename if `.oxlintrc.json` already exists — `lt fullstack update` did it. Otherwise:

```bash
git mv oxlint.json .oxlintrc.json
```

and drop `--fix-suggestions` from `lint:fix`. Either way, add the `overrides` block for
`scripts/**` from the template's `.oxlintrc.json` by hand. Expect warnings the moment the file loads — the rules
were never applied before. They are warnings, so `pnpm run lint` still exits 0.

### 6. Fix the page language

The template always rendered `<html lang="en">`, even with `lang: 'de'` under
`app.head.htmlAttrs`: nuxt-seo-utils writes the site locale into that attribute, and without
`site.defaultLocale` the locale falls back to `en`. Since nuxt-seo-utils 8.5 the dev server
warns about it at startup. Add the language your app actually uses:

```ts
// nuxt.config.ts
site: {
  defaultLocale: 'de', // must equal app.head.htmlAttrs.lang
  // …
},
```

Check with `curl -s http://localhost:3001/ | grep -o '<html[^>]*>'`.

### 7. Re-check the overrides

`lt fullstack init` hoists the app's overrides into the monorepo root's
`pnpm-workspace.yaml`, so the entries listed above may sit there. Before deleting any of
them, prove it in **your** tree, because the answer depends on what your lockfile resolves:

1. Copy `package.json` and `pnpm-workspace.yaml` (without the entry) into a scratch
   directory, with **no** `pnpm-lock.yaml` and **no** `node_modules`. pnpm silently reuses
   `node_modules/.pnpm/lock.yaml` as a resolution hint when the lockfile is missing.
2. `pnpm install --lockfile-only`, then `pnpm audit`.
3. No advisory for that package → the entry is dead. Remove it, then re-resolve the real
   lockfile the same way (delete `pnpm-lock.yaml` **and** `node_modules`, `pnpm install`).

Removing entries against the old lockfile is not enough. When the template did that, three
high advisories came back until the lockfile was re-resolved: the lockfile still recorded
the versions the overrides had once replaced.

### 8. Update the dependencies

In `projects/app/`:

```bash
pnpm add @lenne.tech/nuxt-extensions@1.18.2
```

No code change is needed. If you worked around the SSR hang by calling `validateSession()`
only in `onMounted`, that keeps working. If your `pnpm-workspace.yaml` carries the
`'@nuxt/ui@<4.7.2'` override, widen its key to `'@nuxt/ui@<4.8.1'` and point it at the
`@nuxt/ui` version the app itself uses. Newer oxfmt and oxlint versions may reformat or flag
code the old ones accepted — run `pnpm run format` and `pnpm run lint` once after raising them.

## Verify

```bash
pnpm run check
```

Every step green, including `server-start`, and no `node .output/server/index.mjs` process
left behind (`pgrep -fl .output/server`).
