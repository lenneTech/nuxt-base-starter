# Migration Guide — 2.32.2 → 2.33.0

Version 2.33.0 moves better-auth to 1.7.12 in lock-step with `@lenne.tech/nest-server` 12.0.0 and
`@lenne.tech/nuxt-extensions` 1.20.0, and brings every other dependency up to date. Several of these
changes alter what a generated app does, so the template now decides them explicitly:

- `@nuxtjs/seo` 6 bundles **AI Ready** and **Skew Protection** and switches both on by default. The
  template switches both off (reasons below).
- `@nuxt/image` is gone from the template. It was registered but unused, and its `/_ipx` endpoint
  could not have worked in the Docker image anyway.
- The braces audit suppression from 2.29.0 is gone, because GitHub withdrew the advisory.
- A fresh project no longer warns about its localhost site URL on every `pnpm install`.
- Form placeholders meet WCAG AA contrast. Nuxt UI's default fell short in both colour modes.

Projects created with a current `lt fullstack init` get all of it. **Existing projects do not**: the
files involved were copied when the project was created, and `lt fullstack update` does not touch a
project's `package.json`. Step 1 is required for any project that moves its API to nest-server 12.
Step 2 is required in the same commit as any update to `@nuxtjs/seo` 6. Everything else is optional.

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, every path below is relative to `projects/app/` unless it says root.

### 1. better-auth 1.7.12 on both ends

api and app must resolve the same better-auth version: the two halves speak one wire protocol, and a
skew between them breaks flows such as 2FA activation without any unit test noticing.

1. **API first:** update `@lenne.tech/nest-server` to 12.0.0 and follow its migration guide.
2. **App:**

   ```bash
   pnpm add @lenne.tech/nuxt-extensions@1.20.0 better-auth@1.7.12
   pnpm add @better-auth/passkey@1.7.12   # only if the project uses passkeys
   ```

3. **Monorepo:** if the root `pnpm-workspace.yaml` pins better-auth (2.29.0 step 1), raise both
   entries to `1.7.12`.

Verify with `pnpm why -r better-auth @better-auth/passkey` from the workspace root: every line must
read 1.7.12. The `-r` is required in a monorepo: without it pnpm only looks at the root package, which
depends on neither, prints nothing, and a version split between api and app goes unnoticed.

### 2. @nuxtjs/seo 6, with AI Ready and Skew Protection off

Check Node first. `nuxt` 4.6 and `@nuxtjs/seo` 6 require `^24.15.0` on the 24 line. A `node:24-alpine`
image built today is above it; a pinned digest or a local Node may not be (`node -v`).

```bash
pnpm add -D @nuxtjs/seo@6.0.1
```

Add both keys to `nuxt.config.ts` **in the same commit**, next to the other SEO options. Copy the
comments from the template's `nuxt.config.ts` with them, so the next reader knows how to switch a
module back on.

```ts
skewProtection: false,
aiReady: false,
```

Why both are off by default here:

- **Skew Protection** keeps old build assets only while its storage survives between builds. Our
  deploys build a fresh Docker image every time, so it never restores a chunk. What remains (hourly
  manifest polling, a reload on a chunk error, the crawler guard) Nuxt 4.6 already does on its own.
  It still registers a service worker at scope `/` for every visitor. That worker stays in their
  browsers after the module is switched off, and its `recoveryPath` parameter lets a single XSS
  serve attacker HTML on the app's origin for every 404.
- **AI Ready** adds a middleware to every request. A request with an API-style `Accept` header
  (axios' default) is redirected to `<path>.md`, and `Accept: image/webp` gets a 406. It writes
  `Content-Signal: ai-input=yes` into robots.txt, which declares the customer's content free for AI
  input. It warns on every build without a build-time site URL. Without prerendering,
  `/llms-full.txt` and `/sitemap.md` are empty. Google states that it ignores llms.txt.

A marketing or documentation site may want AI Ready. Then configure it deliberately: set
`contentSignal` and a build-time `site.url`. Or just put a static `public/llms.txt` in place, which
needs no module at all. Copying `tests/unit/seo-bundled-modules-contract.test.ts` keeps either
choice explicit.

**Already deployed v6 with Skew Protection on?** Then visitors carry its service worker. Serve this
file as `public/_nuxt-skew-sw.js` for a few weeks: browsers fetch the new version on their next
visit and unregister the worker.

```js
self.addEventListener('install', () => self.skipWaiting());
self.addEventListener('activate', (event) => event.waitUntil(self.registration.unregister()));
```

Further v6 changes that only matter if the project uses them:

| You have                                                       | Then                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OG images enabled                                              | Rename `NUXT_OG_IMAGE_SECRET` to `NUXT_APP_SECRET` (at least 32 characters; `npx nuxt-og-image generate-secret`), in `.env.example` too, and copy `tests/unit/og-image-contract.test.ts` from the template again: the 2.32.2 copy still requires the old name and fails after the rename |
| A pinned `@nuxtjs/robots`, `@nuxtjs/sitemap`, `nuxt-og-image`… | Raise to robots 7, sitemap 9, OG image 7, schema.org 7, seo-utils 9, site config 5, or drop the pin. The build names the module otherwise                                                                                                                                                |
| Server code using `robots:*` / `sitemap:*` hooks               | `ctx.event` is now a `RequestEvent` from `nuxt/server`: read headers with `ctx.event.req.headers.get(...)`                                                                                                                                                                               |
| `#internal/nuxt-robots`, `#schema-org`, `#seo-utils` imports   | Use `#robots/app` or `#robots/server`, `#schema-org/app` or `#schema-org/server`, `#seo-utils/app`                                                                                                                                                                                       |

The full list is in the upstream
[v5 to v6 migration guide](https://nuxtseo.com/docs/nuxt-seo/migration-guide/v5-to-v6).

### 3. Optional: drop @nuxt/image if nothing uses it

```bash
grep -rnE '<NuxtImg|<nuxt-img|<NuxtPicture|<nuxt-picture|useImage\(|\$img\(' app/
```

**No hits:** remove `'@nuxt/image'` from `modules`, the `image: { … }` block from `nuxt.config.ts`
and the dependency (`pnpm remove @nuxt/image`). Nuxt UI's `UAvatar`, `UUser` and the previews in
`UFileUpload` then render a plain `<img>` instead of going through NuxtImg: same picture, no
resizing. If `pnpm why -r sharp` is empty afterwards, the `sharp` build approval and the
`@img/sharp-*` / `@resvg/*` entries in `ignoredOptionalDependencies` can go too.

**Hits:** keep it, and check the image build. If `ignoredOptionalDependencies` lists
`@img/sharp-linuxmusl-x64` / `-arm64` (as the template did until now), sharp has no binary in the
`node:24-alpine` image, and `/_ipx` fails for every raster image. Remove those two (and their
`@img/sharp-libvips-linuxmusl-*` counterparts) and test one `/_ipx/...` URL on the stage.

### 4. Remove the braces suppression

If the project copied it in 2.29.0 step 2, delete the `GHSA-vfj7-8cjw-p6xm` entry and its comment from
`auditConfig.ignoreGhsas` in `pnpm-workspace.yaml` (root, in a monorepo). The advisory is withdrawn;
`check-suppressions` reports the entry as `WITHDRAWN` until it is gone.

### 5. Only with @lenne.tech/bug.lt: the zod override

bug.lt 1.6.9 pins `zod` at 4.1.13, below the fix for GHSA-mrhx-c7xc-m3w5 (high). Copy the
`'@lenne.tech/bug.lt>zod@<4.6.6': 4.6.7` entry with its comment from the template's
`pnpm-workspace.yaml` into the project's overrides (root, in a monorepo). The selector is scoped to
bug.lt on purpose: a bare `zod` key would also pin better-auth's and the api's zod.

### 6. Playwright 1.64.1 together with the CI image

`@playwright/test` and the CI image tag `mcr.microsoft.com/playwright:vX.Y.Z-noble` must match, or every
E2E job fails at browser launch. In an lt-monorepo project, raise the package in `projects/app` and
the image in `.gitlab-ci.yml` (and `.github/workflows/test.yml`, if present) in one commit;
`check:playwright-image` verifies it.

### 7. E2E locators on the toast region

A test that scopes toasts with `getByRole('region', { name: /Notifications/i })` stops matching under
`@nuxt/ui` 4.12 with the German locale. Use `/Benachrichtigungen|Notifications/i`.

### 8. Optional: silence the localhost warning on every install

`nuxt prepare` (the postinstall) warns `[Nuxt Site Config] url "http://localhost:3001" from buildEnv
should not be localhost`. Outside `nuxt dev`, the site env follows Nuxt's `envName`, which is
`production`, and nuxt-site-config rejects a localhost URL there. Add this to the local `.env` and to
`.env.example`, below `NUXT_PUBLIC_SITE_URL`:

```bash
NUXT_SITE_ENV=development
```

**Never set it in a deployment.** `indexable` defaults to `env === 'production'`, so any other value
puts `noindex` on every page. Docker images built from the template strip `.env*` and are not
affected; a deployment that injects variables some other way must not include this one.

### 9. Optional: type-aware lint

The template now lints with type information, so an un-awaited promise in a composable, a util, a
server route or a test fails `lint` instead of surfacing as an unhandled rejection at runtime.

```bash
pnpm add -D oxlint-tsgolint@7.0.2005
```

Then add `--type-aware` to `lint`, `lint:fix` and every `oxlint --fix` entry of `lint-staged` in
`package.json`, and copy the `typescript/no-floating-promises` rule with its comment from the template's
`.oxlintrc.json`. **In vendor mode** (`app/core/` exists) also copy the extended `app/core/**` override: the core
vendored from nuxt-extensions 1.19.1 and older has eight un-awaited promises, and without the override
`lint` fails in every vendor-mode project. Run `pnpm run lint` once: each finding is either a missing `await` (a real bug) or a
deliberate fire-and-forget, which gets `void`. `--type-aware` also enables the type-aware rules of the
active categories; the template had two `restrict-template-expressions` warnings, both fixed with
`String(…)`.

tsgolint reads `.ts`/`.mts` files only. `navigateTo()` or `router.push()` inside a `.vue` file is not
checked, so the rule says nothing about pages and components.

### 10. Optional: placeholder contrast

Every placeholder in a project on Nuxt UI's defaults fails WCAG AA. Lighthouse only reports it where a
USelect or USelectMenu shows one, because those render the placeholder as a real `<span>`. axe does not
check `::placeholder`, so a UInput or UTextarea never shows up in an audit, although its contrast is the same.

Copy the placeholder block with its comment from the template's `app/app.config.ts` into the `ui` object
of your own, and copy `tests/unit/placeholder-contrast-contract.test.ts`. The test reads the neutral
palette from `app/assets/css/tailwind.css`. If your palette is not slate, it computes the ratio for yours,
and its first case (which reproduces 2.56:1 and 3.75:1) needs your own numbers. If a project already sets one
of these slots, merge the class into the existing string instead of adding a second key.

### 11. Optional: dev proxy and page gutter

Both fixes only matter if the project still has the files from the template.

- **Dev proxy:** if `server/api/` holds a route of the app's own besides `iam/[...path].ts` (projects from the
  template have `build-identity.get.ts`), replace the `'/api'` key of the proxy entry in `nuxt.config.ts` with the template's RegExp key and add every own
  route to its negative lookahead. Copy `tests/unit/dev-proxy-nitro-routes.test.ts`: it fails for each
  route the key still forwards to the backend.
- **Gutter:** add `px-4` to the root `div` of each page listed in the table that the project still has,
  next to its `mx-auto`.
