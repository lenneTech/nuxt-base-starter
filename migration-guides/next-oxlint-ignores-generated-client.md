# Migration Guide: oxlint leaves the generated API client alone

`pnpm run generate-types` writes `app/api-client/` from the API's OpenAPI document. The template's
`.oxlintrc.json` linted those files like project code, so `lint` reported whatever the generator
emits. With @hey-api/openapi-ts 0.97 and `@hey-api/transformers`, one project got about 170
warnings and a `typescript/no-floating-promises` error from generated files. The pre-commit hook
and the CI lint job failed on code nobody in the project wrote, and a hand fix was gone after the
next `generate-types`. The template now ignores `app/api-client/**` in `.oxlintrc.json`.

| Project                                                                      | What to do |
| ---------------------------------------------------------------------------- | ---------- |
| Uses `generate-types` and lints `app/api-client/`                            | Step 1     |
| Has its own exception for the generated client already (an override, a path) | Optional   |

No dependency and no API change are needed.

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, the steps happen in `projects/app/`.

### 1. Ignore the generated client, in all three places at once

The three changes belong together. oxlint exits 1 ("No files found to lint") when every path it is
given is ignored. With the ignore alone, every `generate-types` run would fail before oxfmt formats
the client. A commit that stages only the regenerated client would be refused as well.

In `.oxlintrc.json`, at the top level next to `plugins`:

```jsonc
// Generated by `pnpm run generate-types` (openapi-ts.config.ts): a finding there can only be fixed in the
// generator, and a hand fix is gone after the next run. Type checking and formatting still cover it.
"ignorePatterns": ["app/api-client/**"],
```

In `openapi-ts.config.ts`, under `output`, drop `'oxlint'` from the post-processors:

```ts
postProcess: ['oxfmt'],
```

In `package.json`, add the flag to the lint-staged command for `app/`:

```json
"app/**/*.{ts,vue}": ["oxlint --type-aware --fix --no-error-on-unmatched-pattern", "oxfmt"],
```

`ignorePatterns` also applies to a file passed by name, with and without `--type-aware`. lint-staged
therefore skips staged generated files, and still lints the project files staged with them.
`typecheck` still checks the generated types the app imports. The generator still runs oxfmt on its
output, so `format:check` stays as it is. If your project made its own exception for these files,
replace it with these lines.

### 2. Take over the test (optional)

Copy `tests/unit/oxlint-generated-client.test.ts`. It runs oxlint with your `.oxlintrc.json` on
probe files, over `app/` and on single files. It fails in three cases:

- `app/api-client/` is reported;
- the lint-staged command exits 1 when only generated files are staged;
- `postProcess` still runs oxlint.

```bash
pnpm exec vitest run tests/unit/oxlint-generated-client.test.ts
```

## Check it

`pnpm run generate-types` exits 0, and `pnpm run format:check` passes on its output. Afterwards,
`pnpm run lint` reports nothing under `app/api-client/`.
