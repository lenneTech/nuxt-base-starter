# Migration Guide: 4.0.6 — nuxt-extensions 4.0.6 and Nuxt 4.7.0

The template moves to `@lenne.tech/nuxt-extensions` 4.0.6 and Nuxt 4.7.0. Neither asks anything of the
project's code. Two things change in behaviour:

- **After a page load, JWT mode sends the stored JWT from the first request on.** Up to 4.0.5,
  `validateSession()` put the signed-in user into cookie mode until `/iam/token` answered, and
  requests in that window went out without the bearer (measured in the starter's E2E:
  `two-factor/disable` after a reload). With an API on `cookies: false` they worked only because
  nest-server read the JWT cookie, which with `COOKIE_PREFIX` needs nest-server 12.11.2.
- **A signed-in user whose API session is gone is signed out on load.** `validateSession()` used to
  trust the cached user; the page greeted them by name while every protected request failed. It now
  calls `clearUser()` and returns `false` once a direct `get-session` confirmed the session is gone.
  The template's `/auth/callback` already sends a visitor without a session to the login with
  `?error=session_missing`, and the layout ignores the result. A project that calls
  `validateSession()` itself and reads its result gets `false` in that case.

The other change of this release, the login page offering the sign-in methods `/iam/features`
reports, has its own guide: [4.0.6-sign-in-methods-from-features.md](./4.0.6-sign-in-methods-from-features.md).

| Project                                   | What to do    |
| ----------------------------------------- | ------------- |
| Every project                             | Steps 1 and 2 |
| Uses Nuxt DevTools and wants to keep them | Step 3        |

Unchanged on purpose, for the reasons in the [4.0.4 guide](./4.0.4-nuxt-ui-and-tooling.md):

- better-auth and `@better-auth/passkey` stay on 1.7.19, in step with nest-server-starter.
- TypeScript stays on 6.0.3.
- `@vueuse/nuxt` stays on 14.4.0: `@nuxt/ui` 4.13.1 still requires `@vueuse/core` ^14.4.0.

The five overrides in `pnpm-workspace.yaml` stay as they are; each still closes its advisory.

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, `pnpm add` runs in `projects/app/`.

### 1. nuxt-extensions and Nuxt

```bash
pnpm add -E @lenne.tech/nuxt-extensions@4.0.6
pnpm add -E -D nuxt@4.7.0 @iconify-json/lucide@1.2.159
pnpm dedupe
```

`pnpm dedupe` brings every `@nuxt/kit` to 4.7.0. One copy of 4.2.1 stays: `@lenne.tech/bug.lt`
pins it exactly.

### 2. Check that nothing else moved

```bash
pnpm audit         # No known vulnerabilities found
pnpm peers check   # No peer dependency issues found
pnpm run check
```

### 3. Optional: keep Nuxt DevTools

Nuxt 4.7.0 no longer installs `@nuxt/devtools`. It depends on `@nuxt/devtools-onboard` instead,
which in `nuxt dev` adds a small script to every page that offers to install DevTools. The install
runs only after you confirm it in the terminal, and without a terminal it is refused. Builds,
production and tests without `nuxt dev` are unaffected. The template follows Nuxt here and carries
no DevTools; the lockfile loses `@nuxt/devtools` and 31 packages it pulled in.

To keep them, install the version the starter carried up to 4.0.5, spelled out:

```bash
pnpm add -E -D @nuxt/devtools@3.4.4
pnpm peers check   # No peer dependency issues found
```

Measured on 2026-11-25 with Nuxt 4.7.0: `pnpm peers check` and `pnpm audit` stay clean, and `nuxt dev`
starts DevTools 3.4.4 (Shift + Option + D). With DevTools installed `nuxt dev` also logs
`[Icon] Collection simple-icons is not found locally`; without them it does not.

Not one of the newer versions, for two reasons:

- **4.2.x turns `pnpm run check` red.** `@nuxt/devtools` 4.2.0 and 4.2.1 require `@vitejs/devtools`
  ^0.8, while the `vite-plugin-vue-devtools` 9.0.0-rc.4 they bring along requires ^0.7.6, so
  `pnpm peers check` fails with `unmet peer @vitejs/devtools`. The install button the onboarding
  script shows in the browser installs `@nuxt/devtools@^4.2.0`, so it ends the same way; install
  from the terminal instead.
- **Never without a version.** The npm tag `latest` of `@nuxt/devtools` points at 1.7.1, an old line
  published after 4.2.1, and a bare `pnpm add -D @nuxt/devtools` installs that.

## Check it

In JWT mode (an API with `cookies: false`), reload a page while signed in and watch the network tab:
the first authenticated request carries `Authorization: Bearer …`.
