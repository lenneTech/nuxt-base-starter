# Migration Guide: the deepmerge suppression goes

GitHub withdrew GHSA-gcqx-w48m-w2h4 (deepmerge <=4.3.1) on 2026-11-16. Since starter 2.33.1 the
template suppressed it in `auditConfig.ignoreGhsas` of `pnpm-workspace.yaml`, and the 2.33.1 guide
(step 2) asked projects to copy the entry. The template drops it, so `ignoreGhsas` is empty.

A project with the template's guards has a red `check` since that day, without any change of its
own:

```
✗ WITHDRAWN      GHSA-gcqx-w48m-w2h4  advisory withdrawn on 2026-11-16
[suppressions] OBSOLETE 1 of 1
```

`pnpm run check:overrides` reports the same entry as `FIX AVAILABLE … the advisory was WITHDRAWN`.

| Project                                                   | What to do |
| --------------------------------------------------------- | ---------- |
| Has `GHSA-gcqx-w48m-w2h4` under `auditConfig.ignoreGhsas` | Step 1     |
| Never added it                                            | Nothing    |

deepmerge 4.3.1 stays in the tree. Nothing changes in `package.json` or the lockfile.

## Upgrade steps (existing project)

In an `lt fullstack` monorepo the CLI hoists `auditConfig` to the root, so the entry is in the root
`pnpm-workspace.yaml`, not in `projects/app/`.

### 1. Remove the entry

Delete the `- GHSA-gcqx-w48m-w2h4` line from `auditConfig.ignoreGhsas`, together with the comment
above it. If it was the only entry, write the list explicitly empty:

```yaml
auditConfig:
  ignoreGhsas: []
```

Keep the `[]`. A bare `ignoreGhsas:` reads as `null`, and `check-overrides.mjs` warns on every
run about a declared key it found no entries under, unless the list is written as `[]`.

## Check it

```bash
pnpm audit                    # No known vulnerabilities found
pnpm run check:suppressions   # [suppressions] none declared
pnpm run check:overrides      # [overrides] ok …
```

In a monorepo run the three in the root. If `pnpm audit` reports deepmerge again, the advisory is
back: restore the entry from the 2.33.1 guide and its reasoning, and check that deepmerge still
reaches the project only through build tooling (`pnpm why -r deepmerge`).
