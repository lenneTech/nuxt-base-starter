# Migration Guide — 2.38.0 → 2.38.1: the 2FA page keeps the session token out of a script-readable cookie

**Security fix. Every project with two-factor sign-in needs it.**

nest-server answers the second factor (`verifyTotp`, `verifyBackupCode`) with `{ token, user }`.
`token` is Better Auth's opaque session token: the credential the httpOnly session cookie exists
to keep away from scripts. `app/pages/auth/2fa.vue` stored that token in `jwtToken`, which
nuxt-extensions keeps in the cookie `lt-jwt-token` (or `<prefix>-jwt-token`). That cookie is
readable by JavaScript and lives for seven days. In the default cookie mode a single XSS on any
page of the app was therefore enough to read the session token of every user who had signed in
with 2FA, and to use it. The fallback through `getSession()` did the same with the session's token.

2.38.1 never takes a token from an answer. The page signs the user in on the session cookie
(`setUser(user, 'cookie')`) and asks `/iam/token` for a JWT (`switchToJwtMode()`), as it already
did when no token came back. A session token an earlier version stored in `lt-jwt-token` is
removed once the user completes the second factor again.

| Project                                      | What to do         |
| -------------------------------------------- | ------------------ |
| Uses the 2FA page (`app/pages/auth/2fa.vue`) | Steps 1 and 2, now |
| Has no two-factor sign-in                    | Nothing            |

## What changed

| Area         | Change                                                                                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **2FA page** | `onSubmit` reads only the user from the answer or from `getSession()`, signs in with `setUser(user, 'cookie')` and `switchToJwtMode()`, and removes a non-JWT `lt-jwt-token` |
| **Tests**    | New `tests/unit/pages/auth-2fa.test.ts`; step 5 of `tests/e2e/auth-lifecycle.spec.ts` checks that every `*jwt-token` cookie holds a JWT, never the session token             |

### 2. Take over the tests

Copy `tests/unit/pages/auth-2fa.test.ts`. It runs in every project and fails against the old page.

Add the check to step 5 of `tests/e2e/auth-lifecycle.spec.ts`, after the line that waits for the
user's address on `/app`:

```ts
const cookies = await page.context().cookies();
const sessionToken = decodeURIComponent(cookies.find((cookie) => cookie.name.endsWith('session_token'))?.value ?? '').split('.')[0];
for (const cookie of cookies.filter((candidate) => candidate.name.endsWith('jwt-token'))) {
  expect(cookie.value, `${cookie.name} must hold a JWT, not the session token`).toMatch(/^eyJ[\w-]*\.[\w-]+\.[\w-]+$/);
  expect(cookie.value).not.toBe(sessionToken);
}
```

### A session token already stored in a browser

The old page wrote the session token into `lt-jwt-token`, and the cookie lives for seven days after
it was written. With 2.38.1 the page removes it the next time the user completes the second factor;
otherwise it expires on its own. In your own browser, and in any test browser, delete an
`lt-jwt-token` (or `<prefix>-jwt-token`) whose value is not a JWT (`eyJ….….…`) in the developer
tools under Application → Cookies. nuxt-extensions 1.25.1 will remove such a value on its own.

## Check it

Sign in with a 2FA account and open the developer tools under Application → Cookies. `lt-jwt-token`
is either missing or holds a JWT that starts with `eyJ` and has three parts separated by dots. It is
never the value in front of the dot in the `…session_token` cookie.
