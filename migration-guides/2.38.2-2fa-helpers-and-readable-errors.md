# Migration Guide — 2.38.1 → 2.38.2: the 2FA page signs in through the helpers, and errors read as text

Two follow-ups to the 2.38.1 security fix.

- **The 2FA page.** 2.38.1 taught `app/pages/auth/2fa.vue` itself to store only a JWT. nuxt-extensions
  1.26.0 now does the whole sign-in after the second factor in `useLtAuth().twoFactor.verifyTotp`
  and `verifyBackupCode`: it signs in on the session cookie and fetches the JWT from `/iam/token`,
  or takes the JWT the API answers, and never stores the opaque session token. The page only
  verifies the code and navigates. It no longer touches `jwtToken`, `setUser` or the raw client.
- **Error texts.** The security settings page showed `error.message` raw: "Fehler #LTNS_0002:
  Invalid password" when enabling 2FA, Better Auth's English "Invalid code" when verifying it. The
  2FA page showed "Invalid code" too, because `translateError` translates only coded messages. The
  new `errorText(message, translateError, fallback)` translates a coded message and replaces any
  other one with the page's German text.

| Project                                      | What to do                                                  |
| -------------------------------------------- | ----------------------------------------------------------- |
| On 2.38.1 (nuxt-extensions 1.26.0)           | Steps 1 to 4                                                |
| Not yet on 2.38.1                            | The 2.38.1 guide first; its step 1 raises nuxt-extensions   |
| Has no 2FA page, keeps its own security page | Steps 1 and 3 for readable errors; step 4 only after step 3 |

## What changed

| Area              | Change                                                                                                                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **2FA page**      | `onSubmit` calls `useLtAuth().twoFactor.verifyTotp` / `verifyBackupCode` and navigates; its own token handling and the `getSession()` fallback are gone                                               |
| **Security page** | `app/pages/app/settings/security.vue` shows its four error toasts through `errorText`                                                                                                                 |
| **Helper**        | New `app/utils/error-text.ts`                                                                                                                                                                         |
| **Tests**         | New `tests/unit/utils/error-text.test.ts`; `tests/unit/pages/auth-2fa.test.ts` rewritten for the helpers; `tests/unit/auth/auth-pages-translate-errors.spec.ts` also covers `app/pages/app/settings/` |

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, the steps happen in `projects/app/`.

### 1. Take over the helper

Copy `app/utils/error-text.ts` and `tests/unit/utils/error-text.test.ts`. Nuxt imports the helper
automatically.

### 2. Take over the 2FA page, together with its test

Copy `app/pages/auth/2fa.vue` **and** `tests/unit/pages/auth-2fa.test.ts`. The test is not optional:
the 2.38.1 version fakes `useLtAuth()` without `twoFactor` and fails against the new page.

The page imports nothing from `@lenne.tech/nuxt-extensions` any more, so a vendor-mode project
copies it unchanged. It needs nuxt-extensions 1.26.0 (vendor mode: the core of 1.26.0), where
`useLtAuth().twoFactor` exists and is typed.

A project that changed its copy replaces the body of `onSubmit` with:

```ts
const verify = useBackupCode.value ? twoFactor.verifyBackupCode : twoFactor.verifyTotp;
const { error } = (await verify({ code: payload.data.code })) as { error?: null | { message?: string } };

if (error) {
  toast.add({
    color: 'error',
    description: errorText(error.message, translateError, useBackupCode.value ? 'Backup-Code ungültig' : 'Code ungültig'),
    title: 'Bestätigung fehlgeschlagen',
  });
  return;
}

await navigateTo(redirectTarget.value);
```

and takes `const { twoFactor } = useLtAuth();` in place of `setUser`, `switchToJwtMode`,
`jwtToken` and `useLtAuthClient()`. The type `TwoFactorVerifyResult`, the function `isJwtShaped`
and the import of `LtUserInput` go away.

### 3. Readable errors on the security page

In `app/pages/app/settings/security.vue`, add `const { translateError } = useLtErrorTranslation();`
and replace every `description: error.message || '…'` with
`description: errorText(error.message, translateError, '…')`, keeping the German text. In the
template there are four: deleting a passkey, disabling and enabling 2FA, and verifying the code.

```bash
pnpm run typecheck
```

### 4. Take over the guard

Copy `tests/unit/auth/auth-pages-translate-errors.spec.ts`. It now also fails on a raw
`error.message` in any page under `app/pages/app/settings/`, so take it after step 3, and fix any
other settings page of your own that it names the same way.

## Check it

A wrong 2FA code shows "Code ungültig", not "Invalid code". Enabling 2FA in the security settings
with a wrong password shows the translated text, not "#LTNS_0002: Invalid password". A right code
signs in, and `lt-jwt-token` holds a JWT or nothing.
