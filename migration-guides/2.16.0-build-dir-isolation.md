# Migration Guide — 2.15.x → 2.16.0

Version 2.16.0 stops `pnpm run check` and `nuxt dev` from fighting over one Nuxt
build directory, carries the post-login redirect through every step of the auth
flow, and makes SSR HTML revalidate after a deploy. Greenfield projects created with
a current `lt fullstack init` get all of it automatically. **Forks of the 2.15.x
starter** need the steps below — several of the changes are silent when missed.

## What changed

| Area              | Change                                                                                                                                                                                                                                        |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Build dirs**    | `nuxt.config.ts` reads `NUXT_BUILD_DIR` (default `.nuxt`) and `nitro.output.dir` reads `NITRO_OUTPUT_DIR` (default `.output`). The check chain builds into `.nuxt-check`; `lt dev test` uses `.nuxt-test` / `.output-test`                    |
| **New tsconfigs** | `tsconfig.check.json`, `tests/tsconfig.check.json`, `tsconfig.tests.check.json` — gate twins of the editor configs, re-pointed at `.nuxt-check/`                                                                                              |
| **New scripts**   | `build:check`, `prepare:ide`. `clean` / `reinit` now also remove the new dirs                                                                                                                                                                 |
| **DX change**     | `check` no longer refreshes the IDE's `.nuxt/` — use `prepare:ide` (see below)                                                                                                                                                                |
| **Gate coverage** | `lint` and the type-check now cover `server/`, which no gate reached before                                                                                                                                                                   |
| **Portability**   | Scripts that set env vars use `cross-env` (now a declared devDependency, previously fetched over the network by `npx` at every call). `scripts/check.mjs` passes an env object to `spawn` instead of building a POSIX-only `VAR=value` prefix |
| **Auth redirect** | `?redirect=` now survives the 2FA and e-mail-verification steps; validation moved to `app/utils/safe-redirect-target.ts` and is used by all four consumers                                                                                    |
| **SSR caching**   | New Nitro plugin sends `Cache-Control: private, no-cache` + `Vary: Cookie` on SSR HTML                                                                                                                                                        |
| **Icon endpoint** | `icon.localApiEndpoint: '/_nuxt_icon'` — off `/api/**`, which the Vite dev proxy forwards to the backend                                                                                                                                      |
| **Ignore files**  | `.gitignore` / `.dockerignore` gain the new dirs plus `.nuxt-*` / `.output-*` catch-alls; `.dockerignore` globstars `.git`, `.npm`, `.pnpm-store`                                                                                             |
| **CI**            | Node 22 → 24 (matching the image), `timeout-minutes: 30` on every job                                                                                                                                                                         |
| **Overrides**     | `minimatch` lifted across 5.x–9.x, `postcss` / `tar` raised, a dead `brace-expansion@2.x` key removed                                                                                                                                         |
| **Audit**         | The scaffolder's last high-severity advisory is now CLOSED rather than suppressed — `brace-expansion` raised to 5.0.8 plus a one-line `patchedDependencies` entry for `minimatch@3`. `pnpm audit` reports no known vulnerabilities            |

## Why the build-dir split

`nuxt dev`, `nuxt prepare` and `nuxt build` all write their generated types —
including `tsconfig.json` — into the build dir. With a single shared `.nuxt/`, a
parked dev server rewrites that file in place while the check chain's type-check is
reading it. The run then fails with a flood of TS2307 on every `~`/`#` alias plus
TS1378, on code that is perfectly fine. It reads exactly like a real type error, so
it costs a debugging round every time.

Giving the gates their own `.nuxt-check/` lets `check` and `dev` run in parallel.
`tests/unit/nuxt-builddir-isolation.test.ts` pins each link of that chain, so a later
edit that quietly re-points a gate at the dev directory fails the unit suite instead
of resurfacing months later as a phantom type error.

`buildDir` and Nitro's `output.dir` are unrelated knobs, so the second half
(`NITRO_OUTPUT_DIR`) is a separate axis: `lt dev test` serves the production bundle
and rebuilds on every run, which used to overwrite the `.output` a local
`pnpm run build` had left behind.

## Upgrade steps

### 1. Copy the three gate tsconfigs

Copy `tsconfig.check.json`, `tests/tsconfig.check.json` and
`tsconfig.tests.check.json` from the 2.16.0 template. Each is its editor twin with
the extends chain re-pointed at `.nuxt-check/`. **Keep them in lockstep with your
editor configs** — a `compilerOption` added to one but not the other silently weakens
the gate. The unit guard compares them structurally and fails if they drift.

### 2. Add the config levers

```ts
// nuxt.config.ts
buildDir: process.env.NUXT_BUILD_DIR || '.nuxt',
nitro: {
  output: {
    dir: process.env.NITRO_OUTPUT_DIR || '.output',
  },
},
```

`||`, not `??`. An exported-but-empty `NUXT_BUILD_DIR=` is falsy but not nullish, so
`??` forwards `''` — and an empty build dir resolves to the project root, i.e. Nuxt
writes `tsconfig.json` / `nuxt.d.ts` / `types/` straight over your checked-in sources.

Do **not** pin `nitro.output.publicDir` / `serverDir`: they default to
`{{ output.dir }}/public` and `/server` and follow the redirect on their own. Pinning
one freezes it on `.output` while `output.dir` moves, and the bundle is then written
to one tree and served from another.

### 3. Update the scripts

```jsonc
"build:check":     "cross-env NUXT_BUILD_DIR=.nuxt-check nuxt build",
"prepare:ide":     "nuxt prepare",
"typecheck:tests": "cross-env NUXT_BUILD_DIR=.nuxt-check nuxt prepare && tsc --noEmit -p tsconfig.tests.check.json && tsc --noEmit -p .nuxt-check/tsconfig.server.json",
"lint":            "oxlint app/ server/",
"clean":           "npx rimraf .nuxt .nuxt-check .nuxt-test .output .output-test",
```

and prefix the `pnpm install` / `pnpm audit` steps of your `check:*` chains with
`cross-env NUXT_BUILD_DIR=.nuxt-check` — those fire `postinstall: nuxt prepare`,
which inherits the env of whatever triggered the install.

`cross-env` must be a **declared devDependency**: `npx cross-env` resolves over the
network on every call, which fails in an offline or locked-down CI.

Leave `init` / `reinit` unpinned — they are what keeps the IDE's `.nuxt/` supplied.
Leave `build` unpinned too; the image build runs in its own container and gains
nothing from a second intermediate directory.

### 4. Update the ignore files

`.gitignore`:

```gitignore
.nuxt-check
.nuxt-test
.output-test
.nuxt-*
.output-*
```

`.dockerignore` — note the globstar is load-bearing. Docker anchors a slash-free
pattern at the **context root**, so a bare `.nuxt-check` excludes nothing once the
template sits at `projects/app` in a monorepo:

```dockerignore
**/.nuxt-check
**/.nuxt-test
**/.output-test
**/.nuxt-*
**/.output-*
```

**In an `lt fullstack` monorepo, mirror these into the monorepo-root
`.dockerignore` as well.** Docker never reads `projects/app/.dockerignore` for a
root-context build, so entries that live only in the template have no effect on the
production image — and because `COPY ${APP_DIR}/` sits directly above the expensive
`nuxt build` layer, a stray `.output-test` busts the build cache on every local
`lt dev test` run.

### 5. Adopt `prepare:ide`

This is the one behaviour change that will otherwise be mistaken for a bug. Before
the split, `typecheck:tests` ran a bare `nuxt prepare`, so running the gates
regenerated the editor's `.nuxt/` as a side effect. That reflex is gone: after a
`check`, your IDE may show errors on code that compiles fine. Run
`pnpm run prepare:ide`.

### 6. Route every `?redirect=` read through one validator

Copy `app/utils/safe-redirect-target.ts` and its spec, then replace **every** direct
read of `route.query.redirect`. In the 2.15.x starter `guest.global.ts` read it raw
with an `as string` cast, and `2fa.vue` dropped it entirely — so deep links died for
every 2FA-enabled account while working for everyone else.

```ts
// before — guest.global.ts
const redirect = to.query.redirect as string;
return navigateTo(redirect || '/app');

// after
return navigateTo(safeRedirectTarget(to.query.redirect));
```

If your project adds its own intermediate auth step, carry the query into it or the
deep link dies there.

### 7. Decide on the SSR caching default

`server/plugins/html-no-cache.ts` makes every SSR HTML response revalidate, so a
browser cannot boot a stale post-deploy document that references old bundle hashes.
It bails out when `routeRules` already set a `cache-control`, so an `swr`/`isr` setup
of yours keeps working.

If you front the app with a CDN and would rather solve this with build-manifest
polling, delete the file and lower `experimental.checkOutdatedBuildInterval`
instead — Nuxt's app manifest already self-heals, just one stale boot later.

### 8. Check the icon endpoint

If you kept the default `/api` dev proxy, adopt `icon.localApiEndpoint: '/_nuxt_icon'`.
Otherwise the Nuxt Icon fallback endpoint (`/api/_nuxt_icon/:collection`) is forwarded
to your backend, which answers 404 — and any icon that misses the client bundle (a
runtime name like `i-lucide-${key}`) silently fails to render, with only a console
warning to say why. If you narrowed or removed the proxy, this override can be
reverted.

## Verifying

```bash
pnpm run clean
pnpm run check          # must pass with a `nuxt dev` running in another terminal
pnpm run prepare:ide    # IDE types back on .nuxt/
```

The unit suite is the real gate: `tests/unit/nuxt-builddir-isolation.test.ts` fails if
any link of the isolation chain is missing, and it is deliberately written to fail
loudly rather than pass vacuously.
