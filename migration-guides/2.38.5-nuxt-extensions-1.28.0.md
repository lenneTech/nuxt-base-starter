# Migration Guide — 2.38.4 → 2.38.5: nuxt-extensions 1.28.0, Tailwind scans its components, the admin plugin is off

2.38.5 makes three changes:

- **nuxt-extensions 1.28.0.** A fix release: one authenticated fetch with JWT renewal, error
  translations that no longer hold back the client start, and `LtTransitionFade` /
  `LtTransitionFadeScale` durations that work under Tailwind 4. See its
  [release notes](https://github.com/lenneTech/nuxt-extensions/releases/tag/1.28.0).
- **Tailwind scans the nuxt-extensions components.** In npm mode the `LtTransition*` components
  got no CSS for their movement, and now they do.
- **Better Auth's admin client plugin is off.** nest-server serves no admin routes, and nothing in
  the template calls them.

| Project                                                           | What to do                                                      |
| ----------------------------------------------------------------- | --------------------------------------------------------------- |
| npm mode (`@lenne.tech/nuxt-extensions` in package.json)          | Steps 1 to 5                                                    |
| vendor mode (`app/core/VENDOR.md` exists)                         | Steps 1, 4 and 5; step 3 if you want the guard                  |
| The project's API registers Better Auth's `admin()` plugin itself | Keep `enableAdmin: true`, skip steps 4 and 5 for the admin part |

No API change is needed. nuxt-extensions 1.28.0 declares `@nuxt/ui >=3.0.0` and `tailwindcss >=4.0.0`
as optional peers; every project made from this template meets both.

## nuxt-extensions 1.28.0

The release changes no option, runtime config or environment variable. Three things can still
reach a project's own code:

- **`resetLtAuthClient()` is gone.** It was never exported from an entry point. If your code calls
  it anyway, use `resetLtAuthClientSingleton()` from `@lenne.tech/nuxt-extensions/lib`.
- **`LtAuthResponse` is deprecated.** No function returns or accepts it; it will be removed later.
- **Error translations load after the mount.** Until `GET /i18n/errors/<locale>` has answered,
  `translateError` returns the developer message, and templates switch to the translation when it
  arrives. Code that reads a translation once during setup and keeps the string sees the developer
  message; read it where it is rendered, or `await loadTranslations()` first.

`LtTransitionFade` and `LtTransitionFadeScale` used the Tailwind 3 syntax
`duration-[--start-duration]`, which Tailwind 4 compiles to an invalid declaration, so they faded in
0 s. 1.28.0 uses `duration-(--start-duration)`. In npm mode the classes also need step 2.

## Tailwind scans the nuxt-extensions components

Tailwind 4 generates only the classes it finds in its sources. In a Nuxt app these are the app
directory and every `@source` of the stylesheet; `node_modules` is not among them, and Nuxt UI adds
only the app directories. The `LtTransition*` components of `@lenne.tech/nuxt-extensions` style
themselves with Tailwind classes, so in npm mode their classes were never generated:
`LtTransitionSlide`, `LtTransitionSlideBottom` and `LtTransitionSlideRevert` did not slide, and
`LtTransitionFadeScale` did not scale. Nothing reported it, because a class that is never generated
is no error.

In vendor mode the components sit in `app/core` and were always scanned with the app. The new line
is harmless there, because Tailwind ignores a `@source` path that does not exist.

## Better Auth's admin client plugin is off

`ltExtensions.auth.enableAdmin` adds Better Auth's admin client plugin to the auth client
(`admin.createUser`, `admin.setUserPassword`, `admin.listUsers`, …). nest-server registers no
`admin()` plugin, so every one of these calls answers 404, and `/iam/features` reports no admin
feature. The template calls none of them: its admin area goes by the user's role (`isAdminUser` in
`app/middleware/admin.global.ts`), which this option does not touch. nuxt-extensions defaults the
option to `true`, 1.28.0 too, so removing the line is not enough; the config has to say `false`.

If your API registers `admin()` itself, keep `true`. Note that nuxt-extensions passes the passwords
of `admin.createUser` and `admin.setUserPassword` through unhashed, unlike sign-in and sign-up, so
those routes need the same password normalisation on the API side (see the comment on `admin` in
nuxt-extensions' `runtime/lib/auth-client`).

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, the steps happen in `projects/app/`. The path in step 2 is the same
there: pnpm links the package into `projects/app/node_modules` also with `shamefullyHoist: true`.

### 1. Update nuxt-extensions

npm mode, in `package.json`:

```json
"@lenne.tech/nuxt-extensions": "1.28.0",
```

then `pnpm install`. pnpm holds back packages younger than a day unless `minimumReleaseAgeExclude`
lists `'@lenne.tech/*'`, as the template's `pnpm-workspace.yaml` does.

Vendor mode: bring `app/core` to 1.28.0 the way your project updates its vendored core
(`app/core/VENDOR.md`).

If your code calls `resetLtAuthClient()`, switch to `resetLtAuthClientSingleton()` (see above).

### 2. Add the source line

In `app/assets/css/tailwind.css`, directly after the two imports:

```css
@import 'tailwindcss';
@import '@nuxt/ui';
@source '../../../node_modules/@lenne.tech/nuxt-extensions/dist/runtime';
```

The path is relative to the stylesheet. If your stylesheet lives somewhere else, adjust the number
of `../` so that it ends in the project's `node_modules`. A wrong path fails silently, which is why
step 3 exists.

### 3. Take over the Tailwind test

Copy `tests/unit/tailwind-sources.test.ts`. It reads the classes from the components (from
`app/core` in vendor mode, from `node_modules` otherwise), runs the compiler and scanner that
`@tailwindcss/vite` uses on your stylesheet, and fails with the list of classes Tailwind would not
generate. It reads `app/assets/css/tailwind.css`; if your stylesheet lives somewhere else, change
`STYLESHEET` at the top of the test.

Without the line from step 2, an npm-mode project fails here with `translate-x-full`,
`translate-y-full`, `scale-95` and the other classes of the components.

### 4. Switch the admin plugin off

First check that nothing in your app calls the admin client, whether as `useLtAuthClient().admin`
or through a client you created yourself:

```bash
grep -rnE "(useLtAuthClient\(\)|[Cc]lient)\??\.admin\b|\{[^}]*\badmin\b[^}]*\} = useLtAuthClient" app/ server/
```

Then, in `nuxt.config.ts`, under `ltExtensions.auth`:

```ts
enableAdmin: false,
```

If your unit tests mock the runtime config (as the template's `tests/unit/mocks/nuxt-imports.ts`
does), set `enableAdmin: false` there too.

### 5. Take over the tests

Copy `tests/unit/auth-admin-plugin-contract.test.ts`, `tests/e2e/auth-admin-role.spec.ts`, and
`grantAdminRole` from `tests/e2e/helpers/auth-backend.ts`. The E2E spec registers a user, checks that
`/app/admin` sends it back to `/app`, grants the admin role, signs in again, and opens
`/app/admin` and `/app/admin/system`. It fails on any request to `/iam/admin/*` during the walk. If
your admin pages carry other headings than "Administration" and "System", adjust the spec.

Vendor mode: change the spec's import `from '@lenne.tech/nuxt-extensions/testing'` to
`from '../../app/core/runtime/testing'`, as in your other specs. The CLI rewrote those when it
vendored the core, and a copied spec still has the npm path, so `pnpm run typecheck:tests` fails.

The spec needs an API that reads the roles fresh. nest-server answers a user's roles from a
15-second cache, and the role `grantAdminRole` writes into the database does not reach it. Start
the API with `PLAYWRIGHT=true` (nest-server 11.25.6 or later), or run the suite under `lt dev up` /
`lt dev test`, which switch the cache off on their own. Without it, the new sign-in carries no admin
role and the spec fails on `/app/admin`. The template's `docs/e2e-auth.md` now starts the API that
way in every example; take it over too.

```bash
pnpm exec vitest run tests/unit/tailwind-sources.test.ts tests/unit/auth-admin-plugin-contract.test.ts
pnpm exec playwright test tests/e2e/auth-admin-role.spec.ts   # needs the API with PLAYWRIGHT=true, see docs/e2e-auth.md
```

## Check it

Build the app (`pnpm run build`) and search the generated stylesheets for two classes only the
transition components use:

```bash
grep -l 'translate-y-full' .output/public/_nuxt/*.css
grep -l 'var(--start-duration)' .output/public/_nuxt/*.css
```

A match for each means the slide classes and the fade durations are generated. Before the update,
an npm-mode project without these classes in its own code found neither.

Sign in as an admin and open `/app/admin`: the page opens, and the browser's network panel shows no
request to `/iam/admin/`.
